# ASCI 0.4.0 / 0.5.0 范围对齐与决策稿

> **用途**：0.4 / 0.5 会前阅读 + 会上拍板。受众 = 产品 / 研发 / 设计。
> **目标**：把范围、门禁、依赖、待决项和会后动作对齐到同一张表，便于直接拆 issue、排期和追踪风险。
> **状态**：待 review · 2026-06-22。
> **权威边界**：本文只做范围与决策对齐；需求细节以各版 PRD 为准，目标与验收口径以北极星为准，架构裁决以 ADR 为准。

## 0. 一页速览

| 版本 | 版本目标 | 本版交付 | 发布 / 开工门禁 | 本次会议最需要拍板 |
|------|----------|----------|-----------------|--------------------|
| **0.4.0** | 上线「研究空白·小版」：在用户选定的一组文献内，AI 铺对照表、指出空白和冲突，用户拍板 | 1 个新功能：研究空白·小版；2 个优化：证据集/笔记基础体验、安全边界 P0 | 核心实现前先跑抽取质量 spike；公开发布前必须过安全边界 P0 | 抽取深度、证据集多归属是否进 0.4、安全 P1 纳入窗口、对照表列交互 |
| **0.5.0** | 把 ASCI 的文献前门升级为自建、又快又准的检索数据服务，并把研究空白扩到领域级召回语料 | 文献深钻三件套：OpenAlex 元数据 index、智能检索/重排、重点领域全文加速；新功能：研究空白·全前沿版 | 文献深钻先过成本 spike、检索评测 spike；Google Scholar 内联结果先过可行性 spike | 文献深钻 spike 口径、Google Scholar 接入策略与 owner、0.5 验收标准 |
| **0.6+** | 预留实验设计与查询飞轮等后续能力 | 不进入 0.4 / 0.5 主范围 | 实验设计需先谈实验室合作；查询飞轮需重新定义隐私边界 | 本次只确认后移，不展开方案 |

**排序逻辑**：
- **0.4 不依赖 0.5 搜索引擎**：先验证研究空白这个新场景是否成立，同时补齐证据集沉淀和安全发布底线。
- **0.5 是重型基建窗口**：文献深钻一旦成立，研究空白从“所选文献内”自然升级为“领域级召回语料内”。
- **可信底线不变**：AI 负责铺表、找空格、标冲突；用户判断哪个值得做。AI 不替用户下“这是创新点”的结论。

## 3. 0.4.0 范围

### 3.1 目标

0.4 的目标是把“研究空白”作为新场景上线到可验证状态：用户圈定一组文献，AI 抽出“谁做过什么”的对照表，标出空白和结论冲突，每条可溯源，用户拍板后沉淀进证据集。

### 3.2 In Scope

| 模块 | 产品行为 | 研发落点 | 验收口径 |
|------|----------|----------|----------|
| 研究空白·小版 | 从证据集或勾选论文发起；AI 提议对照表列；用户可增删改；AI 填表、标空白和冲突；用户选择值得做的空白并存回证据集 | 复用现有文献解析 / 语义检索 / 证据集能力；右侧新增研究空白表格视图；若改 IPC，按 shared 常量、main handler、preload bridge、renderer 调用四联同步 | 每个非空格子可点回原文；输出范围限定“所选文献内”；零“全世界没人做过 / 这是创新点”措辞；产物可写入证据集并读回 |
| 证据集/笔记基础体验 | 证据集详情页可直接补证据 / 补笔记；一个证据集可多条笔记；笔记和证据并列管理 | 复用既有 `notes:*` / `evidenceSets:*` 通道与证据集服务；承接研究空白产物落库 | 可新增 2+ 条笔记；可分别删除单条笔记 / 证据且不影响其余成员；研究空白产物可完整读回 |
| 安全边界 P0 | 内部 prompt、原始工具数据、敏感信息不从产品出口外泄 | 采用 `docs/specs/0.4.0/prompt-disclosure-redaction-spec.md` 的 P0 门禁清单；复用现有脱敏基建 | debug copy / 导出 / 权限 IPC / 能力包配置页 / 第三方 telemetry / error monitoring / 打包产物 / SDK 注入面逐项“0 命中” |

### 3.3 Out of Scope

| 不做项 | 去向 |
|--------|------|
| 研究空白·全前沿版 | 0.5，依赖文献深钻语料和检索能力 |
| 证据 / 笔记完整多归属、双向链接、知识图谱 | 后续版本 |
| 安全边界 P2 上线后治理 | 0.5+ |
| 写作包、数据分析包、默认页改造、AI 自动编排多能力、个性化 | 本轮不做 |
| 实验设计 | 0.6+，需先谈实验室合作 |

### 3.4 门禁与依赖

| 类型 | 门禁 / 依赖 | 通过标准 | 未通过时的默认处理 |
|------|-------------|----------|----------------------|
| 核心实现前置闸 | 抽取质量 spike | 真实 15–20 篇论文跑出准确率、单次篇数上限、BYOK 成本三项量化结论 | 缩小单次文献数、减少对照表维度，或推迟核心实现深度 |
| 公开发布门禁 | 安全边界 P0 | spec P0 清单全部通过 | 不公开发布 |
| 功能依赖 | 研究空白沉淀依赖证据集/笔记基础体验 | 对照表 + 选中空白可存入证据集并读回 | 先交付证据集基础能力，再接研究空白沉淀 |

## 4. 0.5.0 范围

### 4.1 目标

0.5 的目标是把 ASCI 的“文献前门”从实时打不稳定外部 API，升级为自建的检索数据服务；同时复用 0.4 的研究空白形态，把输入从用户手头几十篇扩到智能检索召回的领域级语料。

### 4.2 In Scope

| 模块 | 产品行为 | 研发落点 | 验收口径 |
|------|----------|----------|----------|
| 文献语料底座 | 检索不再依赖实时外部源存活；OpenAlex 元数据走自建 index；可合法缓存的 OA 全文进入缓存 | 采用 ADR-013；OpenAlex 全量元数据入服务端 index；可合法再分发 OA 全文缓存；无 API 源按 ADR-014 走用户本地现抓 + 外链，不由 ASCI 服务端自抓 | 同一查询命中本地 index；抽样核验 license；arXiv / 非 OA / NC-ND 不默认入库 |
| 智能检索与重排 | 用户随便一搜，秒回一二十篇紧扣专业的论文 | 混合召回 BM25 + dense；LLM 重排；agentic 迭代检索；检索 / 重排默认跑用户 BYOK；接现有 lit-search 能力包 | 评测集 recall 较裸 BM25 提升；golden path 结果相关；调用链显示推理跑用户 channel |
| 重点领域全文加速 | 命中可合法缓存全文的论文，精读 / 综述秒开；未命中按需现抓、解析、回链 | 复用开源解析能力，不自研；全文 RAG 接入检索到精读闭环 | 命中论文打开精读达秒级；非命中论文可用且缓存合规 |
| 研究空白·全前沿版 | 给定研究方向，系统召回领域级语料，在其上生成对照表、标空白和冲突，用户拍板并沉淀 | 复用 0.4 研究空白产品形态，只替换输入来源为智能检索召回语料；显式披露召回边界 | 每条可溯源；UI 显示搜了哪些源、覆盖范围、可能漏什么；零“绝对全世界没人做过 / 这是创新点”措辞 |

### 4.3 Out of Scope

| 不做项 | 原因 / 去向 |
|--------|-------------|
| 全量语义向量 embedding | 成本与新鲜度对 4 人团队不划算，按 ADR-013 不做 |
| 自托管全量原始全文，包括 arXiv、非 OA、NC-ND | 版权 / 许可红线，只缓存可合法再分发 OA 子集 |
| 查询飞轮 | 0.6 opt-in，涉及查询 / 点击 / 采纳信号和隐私边界重定义 |
| 实验设计 | 0.6+，实验室合作 track |

### 4.4 门禁与依赖

| 类型 | 门禁 / 依赖 | 通过标准 | 未通过时的默认处理 |
|------|-------------|----------|----------------------|
| 基建前置闸 | 成本 / 工程人月 spike | 三档真实月成本与工程投入有量化结论 | 缩小语料范围、调整缓存策略或重排深度 |
| 检索前置闸 | agentic 检索 / 重排评测集 | 自建评测集能量化证明相关性提升 | 先降级为混合召回 + 基础重排，不承诺 agentic 多轮效果 |
| 扩源前置闸 | Google Scholar 可行性 spike | 量化 user-local / 第三方 SERP 接入的可用率、延迟、验证码命中、封锁率、成本 | 不做内联结果，只保留一键直达 GS |
| 功能依赖 | 研究空白·全前沿版依赖文献深钻 P1 / P2 / P3 | 可召回领域级语料、可重排、可溯源、可披露召回边界 | 保留 0.4 小版形态，不宣称全前沿 |

## 5. 实施顺序

```text
0.4（可独立上线，不等搜索引擎）
  并行起步：
    - 安全边界 P0：独立开工，作为公开发布门禁
    - 证据集/笔记基础体验：先补沉淀能力
    - 抽取质量 spike：真实 15–20 篇论文，量化准确率 / 篇数 / BYOK 成本

  spike 出结论后：
    - 研究空白·小版核心：所选文献 → 对照表 → 空白/冲突 → 用户拍板 → 沉淀证据集

0.5（重型文献基建窗口）
  阶段 1：OpenAlex 元数据 index + 成本 spike + 检索评测集 + Google Scholar 可行性 spike
  阶段 2：混合召回 + LLM 重排 + agentic 迭代检索，接现有 lit-search 能力包
  阶段 3：重点领域全文加速 + 研究空白·全前沿版
```

两个执行原则：
- 0.4 先验证新场景价值，避免把搜索引擎基建作为前置依赖。
- 0.5 先把检索底座做稳，再扩大研究空白的输入范围。

## 6. 风险、触发条件与降级策略

| 风险 | 触发条件 | 影响 | 默认降级策略 |
|------|----------|------|--------------|
| 抽取质量不达标 | 15–20 篇真实论文 spike 准确率、篇数或成本不可接受 | 0.4 新功能价值落空 | 缩小单次文献数、减少对照表维度、降低自动化深度 |
| 安全边界 P0 拖期 | P0 清单未全部通过 | 不能公开发布 | 保持 P0 最高优先级，功能可内测但不公开发布 |
| 0.4 范围膨胀 | 多归属、通用 renderer、P1 全量治理等被并入主线 | 主功能延期 | 坚持 0.4 只做基础体验和研究空白最小闭环 |
| 文献深钻成本 / 版权超预期 | 成本 spike 或 license 抽样不达标 | 0.5 基建范围需要收缩 | 缩小缓存范围，只保留合法 OA 子集与按需现抓 |
| 检索效果不够强 | 评测集无法证明相关性提升 | 0.5 差异化不足 | 先交付混合召回和基础重排，延后 agentic 多轮 |
| Google Scholar 不稳定 | 验证码、封锁、延迟或成本超阈值 | 扩源体验不可控 | 只做一键直达 GS，不做内联结果 |

## 附录 A：最小术语对齐

| 词 | 含义 |
|----|------|
| 研究空白 | 把一组文献排成对照表后，没人填的属性组合就是研究空白；外加 AI 标出的结论冲突。0.4 限定“所选文献内”，0.5 限定“召回的领域级语料内”。 |
| 证据集 | 用户围绕一个主题沉淀材料的容器；是研究空白的输入之一，也是产物归宿。 |
| 证据条目 | 指向某来源的引用锚点；对照表里每个填上的格子都需要能溯源到证据。 |
| 笔记 | 证据集里的备注，与证据并列管理。 |
| 对照表 | 不是新术语，就是把一组文献按可比维度铺开的表。 |

一句话：**证据 = 对照表里填了的格子；研究空白 = 对照表里空的格子；用户负责判断哪个空白值得做。**
