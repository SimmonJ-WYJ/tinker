§0

ASCI Agent-Led Principles

Principles · philosophical lens

Agent-solvableobservation / synthesis / annotation / organizationis performed by Agents; users handle onlygoal setting / review / decisions. Agents replace work with standard answers; users retain work without standard answers.

A
Real-time suggestions
Side notes appear during user actions
Evaluate in 0.4+
B
Background batches
Periodically scan workspaces for review queues
Evaluate in 0.4+
C
Event-triggered · preferred
Object changes trigger Agent evaluation and decision cards (Proposals)
✓ 0.2 / 0.3 main path
Key insight:Distinguish writing "this method is useful" (creative thought, user-led), marking "A contradicts B" (relationship observation, Agent-led/user-decided), and writing "I hypothesize X" (assertion registration users may write; Agent should recognize and propose classification).
Gradual fallback criteria (triggered by X1 interviews)
Interview resistance rate Response
≥ 50%Downgrade §0 main path to posture A or B
20% - 50%Retain posture C; add Settings toggle for resistant users
< 20%Keep posture C as the sole main path

Claude Agent SDK recommended multi-Agent architecture

SDK supports two sub-Agent definition methods:Programmatic(preferred for SDK apps, inline main-process configuration) and Filesystem-based(team-friendly, one Markdown file per sub-Agent). They can coexist; programmatic wins on name conflicts.

Method A · Programmatic
Preferred for SDK apps

In query() 's options.agents field, define an inline object. The main Agent needs allowedTools: ['Task'] to invoke sub-Agents.

query({
  prompt: userIntent,
  options: {
    allowedTools: ['Read', 'Task'],
    agents: {
      'paper-search': {
        description: 'Research paper search specialist',
        prompt: 'You are a paper search...',
        tools: ['mcp__arxiv__search',
                'mcp__zotero__add'],
        model: 'sonnet'
      },
      'review-writer': {
        description: 'Review writing and citation tracing',
        prompt: 'You are a review specialist...',
        tools: ['Read', 'Write'],
        model: 'sonnet'
      }
    }
  }
})
Method B · Filesystem-based
Team-friendly

One Markdown file per sub-Agent; YAML frontmatter defines name / description / tools / model, body holds system prompt.

Project directory structure:
