v0.2 详述

§零

ASCI Agent 主导原则

总则 · 哲学滤镜

能用 Agent 解决的观察 / 归纳 / 标注 / 整理由 Agent 完成；用户只承担下达目标 / 审查 / 决策。Agent 替代"有标准答案"的工作，用户保留"没有标准答案"的工作。

A
实时建议
用户操作时浮现旁注
0.4+ 评估
B
后台批处理
周期性扫工作区，产出待审清单
0.4+ 评估
C
触发式 · 首选
对象状态变化时 Agent 自动评估并产出判断卡片（Proposal）
✓ 0.2 / 0.3 主路径
关键洞察：区分原则——写"这段方法可借鉴"（思考创造，用户主导）vs 标"A 反驳 B"（关系观察，Agent 主导用户决策）vs 写"我假设 X"（断言登记，用户可写，Agent 应主动识别并提议归类）。
灰度回退判据（由 X1 访谈触发）
访谈抵触比例 处置
≥ 50%§零 主路径降档为姿态 A 或 B
20% - 50%保留 C 姿态，新增 Settings toggle 服务抵触用户
< 20%维持现状，C 姿态作为唯一主路径
§一

5 大对象 + Proposal 交互对象

Claude Agent SDK 推荐的多 Agent 结构

SDK 提供两种子 Agent 定义方式：Programmatic（SDK 应用首选，主进程内联配置）与 Filesystem-based（团队协作友好，每个子 Agent 一个 markdown 文件）。两者可共存；同名时 programmatic 优先。

方式 A · Programmatic
SDK 应用首选

在 query() 的 options.agents 字段以对象内联定义。主 Agent 需 allowedTools: ['Task'] 才能调用子 Agent。

query({
  prompt: userIntent,
  options: {
    allowedTools: ['Read', 'Task'],
    agents: {
      'paper-search': {
        description: '科研论文检索专家',
        prompt: 'You are a paper search...',
        tools: ['mcp__arxiv__search',
                'mcp__zotero__add'],
        model: 'sonnet'
      },
      'review-writer': {
        description: '综述编写与引用追溯',
        prompt: 'You are a review specialist...',
        tools: ['Read', 'Write'],
        model: 'sonnet'
      }
    }
  }
})
方式 B · Filesystem-based
团队协作友好

每个子 Agent 一个 markdown 文件，YAML frontmatter 描述能力（name / description / tools / model），body 为 system prompt。

项目级目录结构：
.claude/
  agents/
    paper-search.md       # 检索子 Agent
    review-writer.md      # 综述子 Agent
    （未来按场景扩展）

  ⚠ Zotero 不在此目录
    （它是 Skill / MCP 层的资源）
paper-search.md 内容示例：
---
name: paper-search
description: 科研论文检索专家
tools:
  - mcp__arxiv__search
  - mcp__zotero__add
model: sonnet
---
You are a paper search specialist...
⚠ Zotero 不是子 Agent。
子 Agent 按任务类型 / 对话行为划分（如检索 / 综述 / 写作），不按"消费哪个外部资源"划分。Zotero 是系统底座的资源/凭据（位于 Settings → Zotero tab），通过 Skill / MCP 形态被各子 Agent 消费——例如 paper-search 子 Agent 的 tools 列表中含 mcp__zotero__add（入库 MCP），但不存在 zotero 子 Agent。

2. 端到端 RAG 训练方法

RAG 的核心创新在于将检索过程纳入梯度反传链路。[Lewis 2020] 首次提出端到端训练框架，将参数化记忆（生成器）与非参数化记忆（检索器 + 索引）联合优化。在 Natural Questions 数据集上 RAG-Token 取得 56.8 EM 准确率，相比纯参数化的 BART-large 提升 12.4 个点。

证据溯源 EvidenceRef
来源 · Paper · arXiv:2005.11401 · Lewis et al. 2020 · 第 3 节第 2 段
"Our RAG models, fine-tuned end-to-end, achieve state-of-the-art results on multiple knowledge-intensive NLP tasks. Specifically, on Natural Questions, RAG-Token reaches 56.8 EM, outperforming our BART baseline by 12.4 points..."

然而，[Izacard 2022] 后续证明，在开放生成任务上 RAG 反而比纯参数化模型表现稍差（BLEU 低 3 个点），[Asai 2024 · 反驳] 提出 Self-RAG 通过自适应检索机制部分缓解了这个问题。
