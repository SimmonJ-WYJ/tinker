# Isolated macOS Keychain recovery acceptance

**Status** — The real helper reached the Data Protection Keychain. The locally signed build was denied a required entitlement during the first synthetic credential stage. Successful native item operations and full application relaunch with a real credential remain open. Baseline: PR #28, merge `5c9a24d`. Domain contract: [credentialed text preview](2026-11-17-credentialed-text-preview.md).

## Reproduce on a Mac

1. From a fresh checkout with Bun dependencies installed, the Rust toolchain available, and Cargo.lock dependencies cached for offline compilation, run `bun apps/tinker-rust/scripts/build-keychain-acceptance.ts`. The builder prints the exact newly signed temporary bundle path. The output is a diagnostic executable in an app bundle, with the same host identifier and helper identity checks as the ordinary channels preview.
2. Inspect that artifact with `codesign --verify --deep --strict "$bundle"` and `codesign -d --entitlements - "$bundle"`, where `bundle` is the printed path. A successful signature check alone does not grant Keychain access. The local builder uses an ad-hoc signature. To validate positive operations, the signing owner must provide the diagnostic bundle with a provisioning profile authorizing its app identifier and Keychain access group. Run it in a logged-in user context. [Apple TN3137](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains).
3. Run `"$bundle/Contents/MacOS/tinker-channels-preview" --accept-synthetic-keychain`. The diagnostic has no root, item, key or endpoint arguments. It creates a new private profile and service namespace on each run. A zero exit with the lifecycle PASS line records success. A nonzero exit preserves the profile and reports the failing phase. Exit 64 indicates the wrong build or arguments. The build and this check do not require installation.
4. For repeatable synthetic regression on Unix, from `apps/tinker-rust/src-tauri`, run `cargo test --offline --features formal-native-qa --lib credentialed_channels::acceptance:: -- --test-threads=1`. The tests use the existing finite fake vault. The native runner generates fresh random synthetic values. Neither path accepts a tester's API key.

## What the scenario checks

- Use the actual platform store, immutable credential references and existing signed helper. The helper uses private pipes and dynamic code validation. The vault queries the run's service with UI disabled. The endpoint in the synthetic records is reserved under `.invalid`. The diagnostic has no provider transport.
- Create two channels, keep a guard channel, and verify a bound read. Abandon a staged replacement before commit. Reopen the store, verify the previous selection and original secret, and reject the abandoned stage. Commit a replacement, discard its acknowledgment, reopen the store, and replay its receipt. Reject a second installation of that revision. Check the new bound secret, then delete the first channel and verify the guard and its credential still work.
- Logical channel deletion preserves historical references. On successful disposal the diagnostic removes only the specific references returned by its own stages and verifies that no items remain in this run's service. After a lifecycle failure it leaves the fixture intact. On cleanup failure it reports incomplete cleanup and retains the fixture. Do not remove a whole service, change a login Keychain setting, or copy this profile into a tester's app data.
- A separate fault-injection test lets a vault write succeed and loses its reply. On reopen, only the committed channel and its original secret remain authoritative. The unknown reference is never adopted or automatically removed. All fixture material is synthetic.
- The diagnostic reopens the platform store within the same process. Native helper operations each use a child process. Neither substitutes for quitting and relaunching an entitled desktop app. The host integration suite covers fresh-process repair and request counts with synthetic providers separately.

## Evidence and remaining gates

The November 22 macOS arm64 attempt used an ad-hoc bundle with identifier `com.tinker.channels-preview` and no TeamIdentifier. The empty-service preflight succeeded. The first stage returned `vaultMissingEntitlement` (Security.framework `-34018`) and the process exited 1. A read of only the disposable profile showed revision 0, zero channels and zero receipts. No successful native put, rotation, removal, or relaunch with a saved real-vault channel is claimed. Later changes to preserve a failed fixture and reject a wrong build were tested without repeating the entitlement-denied operation. [Apple error reference](https://developer.apple.com/documentation/security/errsecmissingentitlement).

The reserved diagnostic flag and build feature are opt-in. The regular Electron entry, renderer, configuration paths, and profile schemas retain their existing behavior. Ordinary helper callers continue receiving the established safe error for a missing entitlement. Revert this change to remove the diagnostic. An authorized signed QA artifact is needed for the remaining native gates. A live model request, user data migration, and release signing are separate operations.
