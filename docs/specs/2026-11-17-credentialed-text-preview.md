## Design decisions and alternatives

1. Selected: separate credentialed mode with original workbench, native authority and immutable revisions. This can be tested as one real process/UI chain without weakening synthetic-only constructors.
2. Extending the mock overlay alone is smaller but mixes incompatible authority/storage contracts and cannot safely rotate credentials.
3. A detached credential library or CLI is insufficient for the requested application flow. Encryption of JSON with a Keychain master key adds an unnecessary second secret authority and recovery burden.

The user asked to design and implement this stage. Routine implementation details below are resolved within that authorization. Actual user credentials, OS Keychain execution and online paid smoke remain separately unapproved actions and must not be performed here.

## Credential and endpoint contract

- Channel records hold stable channel ID, current revision ID, name, enabled/model metadata and tombstone. Connection revisions retain protocol, normalized base URL and opaque credential reference. No raw key or raw-key hash is a receipt field. New optional catalog schema is strictly versioned and distinct-host gated. Old readers/roots must reject before recovery writes.
- Native transport serializes `channel:create/update/delete` on the existing mutation lane. It stages a nonempty typed key through a private native-only command before the final mutation. Staging token/reference is never placed in the input field. Final receipt input contains reference/keep semantics, not secret. Reuse the same mutation ID/reference across an uncertain-ack reconciliation in that document.
- Stages bind root/store namespace, document generation, channel/create identity and intended mutation. TTL is 120 seconds and outstanding count is 16. Wrong generation/channel/mutation, expired or reused-for-different-intent references fail before network. Reload reads durable catalog/receipt state and never automatically reimports a key or resends a message.
- Each protected immutable credential item also contains its store namespace, stable channel ID, normalized full base URL, protocol and reference. Bound acquisition compares this protected envelope before releasing the key. Catalog/receipt JSON and an unkeyed request digest are not credential authorization: rewriting both must not retarget an existing key. Name, enabled state and model metadata may retain the same binding; changing endpoint or protocol requires a new item. The QA vault persists only finite slot identifiers plus this nonsecret binding, and rejects mismatches. Unbound legacy test items are never upgraded or accepted by the credentialed host.
- Service/account namespace is exact app identity plus stable per-root opaque store namespace and credential reference. No arbitrary vault namespace/path from renderer. Reference generation must be collision-resistant using existing secure platform randomness, not plaintext key digests. Vault put is create-only, never overwrites a reference with different material.
- Safe cleanup considers only exact owned namespace after catalog, pending atomic candidates and runtime recovery are fully validated. Preserve current references and live/accepted leases. Keep historical metadata after obsolete secret cleanup. Committed retired keys may be retained until safe close/reopen to avoid invalidating accepted queues. Failed cleanup retains items, does not claim erasure, and bounded capacity must fail rather than expand. Corrupt/future/uncertain data causes zero vault enumeration/removal.
- A vault helper must not become a public decrypt CLI that inherits the app's Keychain identity. Authenticate its native-host parent using OS process identity and the exact executable plus a private inherited IPC handshake, recheck parent lifetime, and reject direct shell/foreign/helper-parent invocation before any Security.framework call. A caller-supplied nonce, service prefix or renderer flag alone is insufficient. No arbitrary executable, service or command dispatch is allowed. If this boundary cannot be proved, stop that adapter instead of shipping a credential extractor.
- OS vault calls run off actor through an owned bounded helper, never a blocking Security.framework call while holding runtime mutex. Helper mode accepts strict bounded private stdin, clears inherited environment, uses no secret args and no shell, emits only bounded private replies or static errors. Use authentication-UI-fail policy and exact non-synchronizing generic-password queries. Parent owns child, cancels/deadlines and kills/reaps its own process. No actual OS helper call in tests.
- Request preparation uses a shared endpoint policy for chat and catalog. Real DNS uses a short-lived same-binary resolver child with validated host/port only, clear environment, bounded output, at most 16 addresses, two-second total deadline and cancellation kill/reap. Reject private/loopback/link-local/unspecified/multicast including mapped IPv4 in real mode. Pins are per operation, preserve TLS hostname/SNI, and feed existing `new_with_pins`/RejectDns. Numeric owned QA requires no DNS. No credentials/content in resolver IPC.
- Existing run workers may resolve networking, but cancellation must prevent late resolution/vault output from starting HTTP. Provider preparation/secret lookup cannot block actor Stop/close. Retain existing secret echo protection and pre-bind validation when key material is needed. Metadata-only history replay must not eagerly acquire historical keys. Missing current credentials produce a fixed recoverable send/test error, never fabricated provider success.
- Explicit Test/Refresh use authenticated bounded GET `/v1/models` semantics from each supported codec, at most two seconds/64 KiB/128 models. No model POST fallback. Native automatic debounce testing is disabled. Unsupported/malformed catalogs fail explicitly. This stage supports catalog-capable endpoints, not every custom relay variant.
- In credentialed form mode, saved credential presence permits blank-keeps-key editing and saved-channel explicit probes identified by channel ID. `channel:decrypt-key` is unsupported. Show Key only reveals newly typed unsaved content. Endpoint/provider changes cannot forward an old stored credential to a new origin, require an explicit replacement and invalidate stale test evidence. Clear typed replacement after acknowledged save. Layout/controls remain the original workbench.

## Task 2 review corrections

Typed catalog responses are checked after JSON decoding, including object keys and values, against the operation-local credential and the managed known set before model projection. Ephemeral credentials never enter persistent storage or the long-lived known-key cache. Catalog validation is a separate readable function.

Preparation is operation-aware. Fresh sends and saved probes require a newly acquired bound credential for the selected channel; cached leases never substitute for an unavailable current item. Other available current credentials still populate public-write/output guards. Missing or unavailable unrelated items do not prevent explicit replacement, deletion, metadata repair or unrelated execution. Protected-binding and unsafe-storage errors still fail closed. Replacement commit requires acquisition of the newly staged bound item.

Parent live code validation runs in one fixed metadata-only worker initialized by a global OnceLock. Its bounded job/result channels carry only a PID, fixed validation function pointer and static result. An occupied gate prevents queued accumulation; timeout/cancellation does not release it, and only actual validation completion permits another job. A blocked worker is not killed, joined or replaced. The owned-child supervisor keeps the two-second deadline and cancellation active, sends no secret input before successful live validation and a final deadline/cancel recheck, and kills/reaps its own helper when it exits. Late validation replies cannot access that helper or secret pipe. If metadata validation never returns, this process's sole validation worker remains busy until process exit; no real Keychain or positive native item acceptance is implied.
