# Conversation Image and Comparison UI Corrections

Status: the user authorized implementation and submission to GitHub. Initial baseline main c646b75; latest main 4b0ad6a was integrated at submission. Source: feedback from the current Tinker-A project.

<a id="范围与设计"></a>

## Scope and Design

1. Line navigation: gray-black short lines were confirmed on the right of the white conversation view in running version 0.1.606; the source is ScrollMinimap. Remove only its component mount and value import from AgentMessages, retaining the source component and tab preview cache. Normal scrolling, return-to-bottom, and task loading/status remain. Do not delete messages or data.
2. Version comparison: remove the gray container behind the two images, retaining two columns, aligned headings and image tops, natural proportions, and full visibility. Long descriptions no longer consume visual space; retain screen-reader descriptions, explicit parent versions, missing-image notices, closing, and focus return.
3. Sent image references: save structured metadata for the precise original image version in the user message when sending; the backend uses the verified version ledger. Render real thumbnails live and in history, support click-to-view, and degrade gracefully when missing. Continue supporting absent fields in old messages; do not migrate real history or guess images by latest. Retries with the new reference fields reuse the sent message's binding, retain existing payment/retry protection, and issue no new request.

<a id="非目标"></a>

## Non-goals

Do not address the separately recorded billing confirmation policy or simplify Generated by attribution. Do not change the Rust architecture, replace the installed version, call models, or read/write real sessions/keys. The GitHub submission includes only source, tests, and necessary documentation for this round, delivered through a separate branch and PR. Running version 0.1.606 does not update automatically when source changes.

<a id="验证计划"></a>

In the browser, use actual source and mocked APIs to inspect comparison and message lists at desktop/narrow widths. Then run relevant regressions, repository-wide types/tests, and the Electron build, retaining the source diff and project verification records.
