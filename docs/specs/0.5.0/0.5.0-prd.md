## 0. Overview and Positioning

**0.5 in one sentence: upgrade ASCI's literature entry point from live calls to flaky external APIs into a fast, accurate, self-built search data service, expanding research gaps from dozens of user-held papers to all papers in a field.**

Two mutually enabling parts:
- **[Improvement/infrastructure] Complete literature deep-dive stack**: self-built OpenAlex metadata database + AI search/reranking + preparsed OA full-text acceleration for key fields. ASCI's first **data-service foundation**.
- **[New feature] Research Gaps: Full Frontier**: full corpus expands gap identification from the user's dozens of papers to the whole field, unlocking value after the deep-dive foundation exists.

Philosophy: **accumulate relevance, not papers**. Search/reranking defaults to user BYOK (zero per-query inference cost on ASCI servers); servers host only index/corpus, preserving local-first and privacy boundaries.

# Epic 1: Literature Corpus Foundation (Improvement/Infrastructure)

## Problem Statement

Current search: local MCP **live fan-out** to 15+ external APIs, no self-built index/cache. Primary sources sometimes fail wholesale, similar queries fluctuate 0↔45, backups are slow/poor. Three pains: **incomplete retrieval / inaccurate retrieval / slow reading**.

<a id="solution采用-adr-013部分自建分层"></a>

## Solution (ADR-013 Partially Self-Built Layered Approach)

- **Self-built full OpenAlex metadata index** on ASCI servers, extending 0.3.0 cloud/server database retrieval workload; cover long tail and query local index instead of live fan-out.
- **Cache lawfully redistributable OA full text**: peS2o/S2ORC ODC-By, PMC oa_comm CC0/CC-BY. arXiv/non-OA/NC-ND **excluded from ingestion**, fetched on demand + linked.
- Non-API sources such as GS follow ADR-014: **user-local live retrieval + links, never stored**; ASCI servers never scrape them.

## User Stories

1. As a researcher, I want identical queries returned in **milliseconds**, unaffected by source outages, for reliable search.
2. I want long-tail coverage beyond popular libraries, avoiding missing key work.
3. I want non-API sources such as GS through live retrieval/links, covering gray literature/citations/non-English.

## Implementation Decisions

- Architecture, licensing boundaries, GDPR, cost/freshness pipelines **adopt ADR-013/014**, not restated.
- **Revise ADR-002** for retrieval workload: ES/OpenSearch/Typesense selection, storage, freshness pipeline.

<a id="-前置-spikeadr-013-已挂动工前必做"></a>

## 🚧 Prerequisite Spikes (ADR-013, Required Before Starting)

1. **Three real monthly-cost / engineer-month tiers**, internal infrastructure spike unavailable through public lookup.
2. **Agentic search/reranking benchmark**, small self-built evaluation quantifying professional scrutiny; currently only CoRank reranking evidence.

> **GS feasibility was spike③ here, moved to parallel 0.4 exploration** ([0.4 PRD prerequisite exploration](../0.4.0/0.4.0-prd.md)); formal delivery in **Epic 5**, outside E1's start gate.

<a id="验收"></a>

## Acceptance

- Same query hits local index, milliseconds, independent of source health.
- Corpus samples retain per-paper license metadata, NC/ND filtered; arXiv links without caching.
- Legal confirms upstream per-paper filtering policy.

# Epic 2: Intelligent Search and Reranking (Improvement, Core Differentiation)

## Problem Statement

Bare lexical/fan-out recall has poor relevance. Researchers want a casual search to return ten or twenty professionally relevant papers in seconds.

<a id="solutionadr-013-p2"></a>

## Solution (ADR-013 P2)

Differentiate above the corpus with **agentic iterative retrieval** (citation chains/query evolution), **hybrid recall** (BM25 ⊕ dense), and **LLM reranking** (canonical/relevant work in top N). **User BYOK by default**, zero ASCI per-query inference cost. Integrate existing lit-search (searcher/relevance-scorer), not a separate system.

## User Stories

1. I want ten or twenty relevant papers in seconds without repeated keyword tuning.
2. I want multiround citation/query iteration for complex questions rather than single-shot recall, improving completeness.
3. I want my own key to fund intelligent search, keeping ASCI sustainable and costs under my control.

<a id="产品决策2026-06-24-澄清"></a>

## Product Decisions (2026-06-24 Clarification)

- **Visible but collapsed iteration**: transparent multiround work in expandable search-step groups, reusing `search-plan-confirm` initial plans + `execution-step-grouping`; collapsed by default, expandable for review. Reviewability supports trust; collapsed defaults support flow.
- **BYOK costs: light notice + actual usage afterward + internal fallback, no hard user budget gate**: `search-plan-confirm` states multiround work uses your key; show actual usage afterward; internal loop-round cap prevents runaway. Revisit user hard budgets in 0.6 based on real use.
- **Fallback ladder**: confirmation offers `确认执行（智能检索 · 多轮）` (confirm intelligent multiround search) / `我来调整` (adjust) / `单轮检索（混合召回 + 一次重排 · 更省）` (cheaper single-round hybrid + one rerank) / `取消` (cancel). Declining multiround yields single-round results rather than nothing, matching L1/L2/L3 language. Single-round terminology aligns with CONTEXT.md intelligent search; avoid “quick” conflicting with the seconds-level promise.

<a id="验收-1"></a>

## Acceptance

- Benchmark hybrid recall significantly exceeds bare BM25; LLM raises canonical papers to top N; golden path verifies relevant results in seconds.
- Audit shows inference on user channel, server only queries index.
- Point existing lit-search to new index + reranker to enable it.

## Out of Scope

Full-corpus semantic embeddings (200 million+, excluded by ADR-013); query flywheel in 0.6, opt-in after revisiting privacy boundaries.

# Epic 3: Key-Field Full-Text Acceleration (Improvement)

## Problem Statement

Per-paper reading requires live PDF fetch → parse → RAG, taking minutes and delaying reviews.

<a id="solutionadr-013-p3-&#45;adr-014-需求驱动填充"></a>

## Solution (ADR-013 P3 + ADR-014 Demand-Driven Population)

- Reuse open-source SOTA parsing (MinerU/olmOCR), no custom parser.
- Papers in lawfully cached OA corpus open for reading **in seconds**, preparsed/prechunked.
- Others fetch/parse/RAG on demand, caching only within licenses; OA follows ADR-014 demand-driven population with disassociated signals and server-side fetching/parsing, OA only in shared cache.

## User Stories

1. I want key-field papers to open in seconds rather than minutes of parsing, speeding reviews.
2. I want search results to lead directly to deep-reading Q&A, without switching tools.

<a id="产品决策2026-06-24-澄清-1"></a>

## Product Decisions (2026-06-24 Clarification)

- **Three full-text states, marked beforehand with informative progress**, explaining speed differences rather than appearing broken:
  - ① Ready (lawfully cached OA): seconds.
  - ② Fetch needed (uncached OA / arXiv): readable after waiting, explicit PDF fetch → parse → index progress, not a bare spinner.
  - ③ External link only (non-OA / CC-NC/ND): license-limited source navigation, explicitly not a failure.
  - **Mark states on paper entries before action**, reusing search metadata at zero extra cost; keep ready state concise.
- **R4 search→reading loop must ship**, upgraded from degradable under scope-boxed commitment: one-click reading Q&A, no tool switch/reimport. State coverage: ① instant ② after fetch ③ external-only, no deep reading.

<a id="验收-2"></a>

## Acceptance

- Corpus hits open for reading at sub-second/seconds scale; on-demand misses work with compliant caching.
- Parser quality/speed meets baseline, no custom parser.

# Epic 4: Research Gaps: Full Frontier (New Feature)

## Problem Statement

The small version analyzes only dozens of selected papers: trustworthy but narrow. Researchers ask whether a direction is unexplored **across the whole field**. This needs corpus support and can otherwise devolve into AI guessing novelty; implement after the deep-dive foundation.

## Solution

Keep comparison table + gap identification + user decisions, expanding **input from dozens of user-held papers to domain-level intelligently retrieved corpus**:
- Research direction → Epic 2 domain-level recall → comparison table → field-level gaps.
- **Trust boundaries remain**: every gap/conflict traceable; claims limited to this retrieved collection, with **explicit recall boundaries** (sources, coverage, possible omissions), never “absolutely nobody worldwide has done this.”
- Users decide; AI never declares “this is an innovation.”

## User Stories

1. I want AI to map prior work/gaps across a field for my direction, supporting novelty/opportunity assessment.
2. I want clear searched scope and likely omissions to assess confidence boundaries.
3. I want the same comparison/decision experience at larger scope for a smooth transition.

## Implementation Decisions

- Reuse all 0.4 research-gap product forms (table / gaps / decisions / evidence-set retention, [research-gap-spec](research-gap-spec.md) · [#708](https://github.com/OPENSCI-Labs/ASCI-Alpha/issues/708)); **only three changes: input source + scale + stronger disclosure**.
- **Dual input modes** (2026-06-24 clarification 4.2):
  - Retain 0.4 selected-paper mode, tightly scoped and trustworthy, **no regression**.
  - Add field-level recall from a natural-language research direction.
  - **Reuse E2 `search-plan-confirm`**, letting users shape recall boundaries during confirmation, sharing the boundary card's source; trust begins before retrieval, not as an afterward label.
  - Optional seed-paper `@`mentions anchor/bias recall, reusing 0.4 stack.
- **Recall boundary card extends 0.4 trust baseline** (research-gap-spec §5.5; clarification 4.1): upgrade “based on your N papers” to a **persistent, nondismissible** card showing ① sources ② language/time/OA-indexed limits ③ likely omissions: non-English/gray/unindexed long tail. Retain wording hard filters + GF3 regressions. This is the **critical guard** against misreading field-level recall as exhaustive frontier coverage.
- **Two-layer scale handling** (clarification 4.3): recall may yield hundreds/thousands; table is designed for dozens with per-cell extraction cap (0.4 GM7), so **reduce before table construction**:
  - ① Field overview: cheap thematic clustering without cell extraction, carrying boundary card and breadth.
  - ② Drill into topic → unchanged 0.4 table (extraction + combinatorial gaps + conflicts + decisions + retention), within a manageable subset and GM7 cap.
  - Fallback: if clustering stalls, one reranked top-N table + explicit top-N disclosure; **not preferred**, since top-N loses long tail and weakens Full Frontier promise.
- Requires Epics 1–3 (corpus/search/full-text) and prior 0.4 research-gap implementation ([#708](https://github.com/OPENSCI-Labs/ASCI-Alpha/issues/708)).

<a id="验收-3"></a>

## Acceptance

- Direction → domain recall → domain table/gaps; every item traceable.
- Explicit source/coverage/limitation disclosure; regression tests prohibit absolute worldwide novelty or innovation claims.

## Out of Scope

Automatic cross-field research-claim generation; experimental design → 0.6+.

# Epic 5: Non-API Sources / Direct GS Retrieval (New Feature)

## Problem Statement

Epic 2's OpenAlex index covers **open-world metadata long tail**, yet misses gray literature, citation discovery, non-English, theses, and some non-OA. Much lives on **platforms without APIs**, with Google Scholar the reference case. GS lacks API, ToS prohibits scraping, and much full text is non-OA/noncacheable: valuable but technically/legally difficult ([failure expansion spec](../lit-search-failure-source-expansion-spec.md) §4.2 previously blacklisted it as dead).

<a id="solutionadr-014-d1d3"></a>

## Solution (ADR-014 D1–D3)

Search Agent directly fetches GS using our own implementation; **live results + links, never Corpus storage**, matching ADR-013 licensing. **User-local by default**, with three fallbacks. Diagram: L1 local user IP/session, cost=0 with legal risk distributed to users; L2 third-party SERP (SerpApi etc.) with user's BYOK, no ASCI payment; L3 one-click GS web navigation, always available, zero-risk floor when all fetching fails.

```
Search Agent needs GS results
 ├─ L1 primary: user-local retrieval (user IP/session · cost=0 · legal risk distributed to users)
 ├─ L2 fallback: third-party SERP API (SerpApi etc.; user key = BYOK, no ASCI payment)
 └─ L3 safety floor: one-click GS website (always available · zero risk · fallback if all retrieval fails)
```

- **ASCI servers never scrape** (ADR-014 D2: immediate IP blocking, concentrated legal costs, broken BYOK model).
- **Threshold decision** from 0.4: pass → L1 primary; fail → L2 primary, best-effort L1, always L3.
- 0.5 supports **GS alone as reference source**, observation tier; ResearchGate / CNKI / Wanfang / publisher pages → 0.6/V1, gated on GS experience.

## User Stories

1. I want GS gray/non-English/thesis coverage absent from OpenAlex, avoiding missed key work.
2. I want local retrieval or my SERP key, without ASCI funding/server scraping, for sustainability and privacy control.
3. Even if blocked, I want one-click GS web access as a guaranteed fallback.

## Implementation Decisions

- **Prerequisite = 0.4 GS exploration conclusion**, GS-E1~E4 thresholds in 0.4 PRD. If failed, ship degraded tier without blocking other Epics.
- Extend ADR-013 on-demand fetch + links without storage; no new compliance surface, no corpus cache.
- Add GS to existing lit-search normalized sources (8 APIs → +1 non-API), complementing OpenAlex/intelligent search.

<a id="验收-4"></a>

## Acceptance

- Agent obtains L1 local GS results with backlinks and no Corpus storage, verified end-to-end.
- L1→L2 fallback, L3 always available; audit confirms servers never scrape.
- Corpus audit contains no fetched GS content.

## Out of Scope

- Other non-API categories (ResearchGate / CNKI / Wanfang / publisher pages) → 0.6/V1, gated on GS experience.
- GS full-text storage/cache redistribution: never, licensing boundary.
- Demand-driven corpus population (ADR-014 D4–D6 lazy writes): separate area, other half of ADR-014 coverage gap, to be added.
