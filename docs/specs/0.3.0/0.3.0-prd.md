## 0. 概述与定位

**0.3.0 是 ASCI 的首个公开发布版本（macOS 首发，Windows 视 EV 签名 lead-time 决定）。** 截止目标 2026-06-19，约 2 周代码窗口（0.2 Week 3 已重叠启动服务端骨架）。

**四句话定位**：

1. **OPENSCI 账户接入** —— ASCI 不自建账户，统一用 OPENSCI 作为唯一登录入口；强制登录。
2. **能力包配置化（Codex 风开箱即用）** —— 内置 2 个场景能力包默认启用、不可禁用、无需配置；用户在"配置"页看到能力总览，在 Settings 调系统参数。
3. **发布就绪** —— 版本更新、崩溃/行为埋点、GDPR MVP 合规、发布前置 lead-time。
4. **数据可携带** —— 研究数据存本地、可一键导出为开放格式、可删除账户。

**收敛说明**：能力包范式 / Agent 主导哲学（0.2 §零）在 0.3 **收敛为"后台架构 + 配置页展示"**，不在主使用路径强推（默认页改造、Proposal 机制、激活路径均移出 0.3）。0.3 的用户可感知重心是**账户 + 发布就绪 + 数据可携带**，能力包作为底层范式继续沉淀。

**优先级标签**（沿用 north-star）：必做（发布门槛）/ 观察（跟踪不阻塞）/ 可降级（进度不及推 0.4）/ 0.4 二发。

## 1. 领域语言（事实源）

> 0.3 引入的核心领域术语，PRD 全文与后续实现以此为准。

### 数据三分（决定"存哪里 + 跟谁走"）

| 术语 | 定义 | 存储位置 | 归属 |
|------|------|---------|------|
| **研究数据资产（Research Data Asset）** | 用户的研究产物：papers / notes / evidence-sets / evidence-refs / citation-relations / reviews，及其全文/PDF | **本地** `~/.asci/` | **设备级**（单一本地库，账户解耦） |
| **行为遥测（Behavioral Telemetry）** | 用于优化产品的结构化行为信号（崩溃、功能使用、自进化 5 类信号），脱敏、绝不含研究内容 | **服务端** | 按当前登录账户归属 |
| **系统底座凭据（System Foundation Credentials）** | Provider API Key / Zotero 凭据 / MCP 服务器列表 / 代理 | **本地** `~/.asci/` | **设备级**（跨账户共享，一台机器一套） |

> 三分红线：行为遥测**绝不**采集研究数据资产的内容（文献全文 / PDF / 笔记原文 / 对话原文）或凭据（API Key / 邮箱 / 用户名 / 含用户名路径）。

### 能力包 vs Skill

| 术语 | 定义 | 0.3 用户可操作性 |
|------|------|----------------|
| **能力包（Capability Package）** | 面向任务域的开箱即用解决方案（场景 Agent + Skill 引用 + MCP 引用 + UI 框架）。0.3 内置 2 个：文献检索包、文献综述包 | **默认启用、不可禁用、不可卸载/导入**（Codex 风）；包内偏好（如默认模型）可编辑 |
| **Skill** | 单一能力片段（一个 SKILL.md + 实现），被能力包引用，也可独立启停 | **可启用/禁用**；来源两类：系统内置 / 来自能力包 |

### OPENSCI 登录

| 术语 | 定义 |
|------|------|
| **OPENSCI 登录** | ASCI 的**唯一登录入口**。OPENSCI 是身份提供方（IdP），ASCI 通过 OAuth/OIDC 委托其完成身份验证。ASCI 服务端持有自己的用户映射表（OPENSCI uid → ASCI user，仅用于身份与行为遥测归属）；用户 **profile（昵称/头像/机构/学科）读 OPENSCI，只读展示**。Email/Google/ORCID 等具体登录方式由 OPENSCI 提供，ASCI 不自建注册、不自申 OAuth client。 |

# Epic 1：账户体系（OPENSCI SSO 强制登录）

## Problem Statement

ASCI 0.1/0.2 是纯本地无账户应用。公开发布需要用户身份，以便：归属行为遥测优化产品、未来跨设备同步、统一 OPENSCI 生态身份。用户不希望为 ASCI 再建一套账户，也担心强制登录后研究数据被锁在云端、离线/换设备不可用。

## Solution

ASCI 通过 **OPENSCI 作为唯一登录入口**（OAuth/OIDC 委托）完成强制登录——用户用已有 OPENSCI 身份进入，无需新建 ASCI 账户。**研究数据资产仍存本地（设备级单一库）**，账户只是身份标识。登录后 token 本地加密缓存，并明确告知用户"研究数据仅存本地"（**不承诺跨设备同步时间表**），消除"登录了却换设备看不到数据"的预期落差。

> ⚠️ 修订（0.4 grill 2026-06-01）：原承诺"跨设备同步将在 0.4 提供"已**撤销**——0.4 不做 sync，且不再对用户承诺同步时间表（见 [0.4 north-star §六](../../milestones/0.4/north-star.md)）。本 Epic 文案统一为"数据仅本地、不承诺时间表"。

## User Stories

1. 作为新用户，我想用 OPENSCI 账户登录 ASCI，以便用统一身份进入应用、无需另建 ASCI 账户。
2. 作为用户，我想首次打开 ASCI 时看到 OPENSCI 登录入口并跳转授权，以便授权后进入应用。
3. 作为用户，我想登录后 ASCI 只读展示我的 OPENSCI profile（昵称/头像/机构/学科），以便确认身份、无需在 ASCI 重复填写。
4. 作为用户，我想我的登录 token 在本地加密存储，以便退出后 token 不可被恢复。
5. 作为用户，我想 token 过期时自动刷新（旧 token 一次性失效），以便无需频繁重新登录、且旧 token 泄露无效。
6. 作为用户，我想登录后我的研究数据（论文/笔记/证据集/综述）保留在本机，以便研究资产在本地、隐私可控。
7. 作为用户，我想在欢迎页/账户页看到"研究数据仅存本地"的明确说明（不承诺跨设备同步时间表），以便理解换设备暂时看不到数据是预期行为。
8. 作为 0.1/0.2 老用户，我想升级后首次 OPENSCI 登录就直接看到我已有的本地论文库/笔记/证据集，以便无缝继续工作、无需重建数据。
9. 作为老用户，我想升级后 Zotero/Provider API Key/代理/MCP 等系统配置保持不变，以便检索/综述/Zotero 立即可用、无需重填。
10. 作为用户，我想强制登录后才能使用 ASCI 功能，以便行为数据正确归属、享受统一账户体系。
11. 作为同一设备的多账户使用者，我想不同 OPENSCI 账户登录后看到同一份设备本地研究库，以便个人设备上数据连续可用（设备级库语义）。
12. 作为用户，我想随时登出，以便切换账户或保护隐私。
13. 作为离线用户，我想 token 未过期时断网仍能使用本地功能，以便无网/内网/出行场景不被阻断（受 OPENSCI token 机制约束）。
14. 作为用户，我想登录失败/网络异常时有清晰提示与重试入口，以便理解为何无法进入。

## 关键产品决策

- **唯一登录入口 = OPENSCI**：ASCI 不自建 Email/密码注册、密码重置、不自申 Google/ORCID OAuth client（这些归 OPENSCI）。
- **ASCI 服务端持有用户映射表**（OPENSCI uid → ASCI user），仅用于身份与行为遥测归属，不存 profile（profile 实时读 OPENSCI）。
- **强制登录**：所有功能在登录后。
- **研究数据 = 设备级单一本地库**（不按账户隔离，对齐 Zotero），账户仅身份标识；系统底座凭据设备级共享。
- **老用户迁移无认领流程**：本地库即设备库，登录后直接可用。
- **预期管理**：欢迎页/账户页明确"研究数据仅存本地"，**不承诺跨设备同步时间表**，避免强制登录制造的"云数据"落差。
- **依赖**：OPENSCI SSO 接口（OAuth/OIDC）由 OPENSCI 在 0.3 期间并行建设，接口契约需冻结（见 Epic 7）。

## 验收标准

| # | 验收 | 优先级 |
|---|------|--------|
| U-A1 | 走完 OPENSCI 登录链路（授权跳转 → 回调 → 进入应用），登录成功 | 必做 |
| U-A2 | Token 本地加密存储，退出后检查文件 token 不可恢复（继承 0.1 safeStorage） | 必做 |
| U-A3 | Token 刷新后旧 access token 失效（抓包返回 401） | 必做 |
| U-A4 | 0.1/0.2 老用户升级 + 首次 OPENSCI 登录 → 已有本地论文库/笔记/证据集直接可见，Zotero/Provider/代理/MCP 立即可用无需重填 | 必做 |
| U-A5 | 账户 tab 展示 OPENSCI profile（昵称/头像/机构/学科），为只读 | 必做 |
| U-A6 | 欢迎页/账户页含"研究数据仅存本地"明确文案（**不承诺跨设备同步时间表**） | 必做 |

## Out of Scope（本 epic）

跨设备数据同步（0.4）；ASCI 自建注册/密码体系；同机多账户的数据隔离（0.3 为设备级共享）；OPENSCI 账户本身的功能（归 OPENSCI）。

# Epic 2：能力包配置化（Codex 风开箱即用 + 配置页 + Settings 重构）

## Problem Statement

0.2 中能力包是后台概念，用户感知薄弱；Skill/MCP/能力包配置散落、心智混乱。0.3 公开发布需要让用户：开箱即用内置场景能力（无配置负担）、在统一入口理解"ASCI 能做什么"、清晰区分"调系统参数 vs 管 Agent 能力"。

## Solution

内置 2 个能力包（文献检索、文献综述）通过 A3 注册契约接入，**默认启用、不可禁用、无需安装/配置**（Codex 风开箱即用）。左侧"配置"页（已存在）承载 Agent 生态：能力包板块**只读展示**能力构成、Skill 板块**保留启停管理**。Settings 弹窗收敛为 **10 个 tab**（profile → 账户），承载系统底座配置；Skill/能力包不再出现在 Settings，消除双入口分裂。

## User Stories

1. 作为用户，我想 ASCI 开箱即用内置文献检索/文献综述能力，无需安装配置，以便直接下达检索/综述任务。
2. 作为用户，我想在左侧"配置"页看到 ASCI 内置能力包的总览，以便理解 ASCI 能做什么。
3. 作为用户，我想能力包板块只读展示每个包的场景 Agent / 引用的 Skill / 引用的 MCP / UI 框架 / 包内偏好，以便了解能力构成。
4. 作为用户，我想编辑能力包的包内偏好（如该场景默认模型），以便定制场景行为。
5. 作为用户，我想在配置页 Skill 板块看到所有 Skill 及其来源（系统内置 / 来自能力包），以便了解可用能力片段。
6. 作为高级用户，我想启用/禁用单个 Skill，以便调整 Agent 可用能力。
7. 作为用户，我想看到每个 Skill"被哪些能力包使用"的反向链接，以便理解 Skill 与能力包的关系。
8. 作为用户，我想按来源/启用状态过滤 Skill，以便快速定位。
9. 作为用户，我想 Settings 弹窗有 10 个职责清晰的 tab（账户/通用/模型/Zotero/代理/MCP/数据采集/快捷键/已归档/关于），以便系统配置心智清晰。
10. 作为用户，我想 Skill/能力包只在左侧"配置"页出现、Settings 不再有它们的入口，以便配置入口不分裂。
11. 作为检索任务用户，我想右侧产物面板展示检索结果列表（字段标注/来源/引用计数/排序筛选），以便审阅检索产物。
12. 作为综述任务用户，我想右侧产物面板展示综述正文 + 段落溯源（可点击引用），以便追溯综述依据。
13. 作为老用户，我想升级后旧 Settings"配置"tab 的内容自动迁移（MCP 进 MCP tab、能力包/Skill 进左侧配置页），以便升级无感。
14. 作为用户，我想 MCP 服务器在 Settings 独立 MCP tab 配置，以便作为系统层基础设施被多个能力包消费。

## 关键产品决策

- **官方能力包默认启用、不可禁用、不做本地导入/卸载**（Codex 风）；移除代码现有的启停 toggle。

# Epic 3：埋点（崩溃 + 行为 + 自进化）

## Problem Statement

公开发布需要数据基础来定位崩溃、理解功能使用、为未来 Agent 优化攒数据。但科研用户高度重视隐私，欧盟用户受 GDPR 约束（非必要采集需显式 opt-in），绝不能采集研究内容。

## Solution

三层埋点：**Sentry** 收崩溃（脱敏）、**PostHog** 收产品行为、**自进化端点**收 5 类结构化信号（独立通道）。地域分支：欧盟 IP 默认 opt-in（关）、非欧盟 opt-out（开）。数据采集 tab 提供两条独立开关 + 说明。严守红线：绝不采集研究内容与凭据。

## User Stories

1. 作为产品团队，我想未捕获异常自动上报 Sentry（含堆栈），以便定位崩溃。
2. 作为用户，我想崩溃上报不含我的个人信息（邮箱/IP 脱敏），以便隐私受保护。
3. 作为用户，我想崩溃堆栈中本地文件路径的用户名段被替换为占位符（`/Users/<USER>/`、`C:\Users\<USER>\`），以便路径不泄露身份。
4. 作为产品团队，我想关键功能事件（检索、综述生成、登录）上报 PostHog，以便分析功能使用。
5. 作为欧盟用户，我想非必要采集默认关闭、需我显式开启（opt-in），以便符合 GDPR。
6. 作为非欧盟用户，我想采集默认开启但可随时关闭（opt-out），以便保留控制权。
7. 作为用户，我想在数据采集 tab 看到 PostHog 与自进化两个独立开关及简要说明（独立通道、绝不采集内容、可随时关闭），以便分别控制。
8. 作为产品团队，我想自进化埋点采集 5 类结构化信号（任务结构、工具使用、模型选型、错误异常、工作区结构）+ 用户隐式反馈（复制/保存/引用/丢弃/赞踩/重试），走独立后端通道，以便为 0.4 Agent 优化攒数据且与行为埋点物理隔离。
9. 作为用户，我想自进化埋点绝不采集我的文献全文/PDF/笔记原文/对话原文/凭据，以便内容隐私绝对安全。
10. 作为用户，我想关闭自进化 toggle 后端点不再收到我的事件，且不影响 PostHog 状态（两开关解耦）。
11. 作为外部审计员，我想能根据仓库内 schema 还原可采集字段范围（不读源码），以便核验数据最小化。

## 关键产品决策

- **三层**：Sentry 崩溃（脱敏，含 T4a 路径用户名段替换）；PostHog 行为；自进化 5 类信号（独立端点，与 PostHog 物理隔离）。
- **自进化去 Proposal 信号**：原 6 类中"用户反馈"的 Proposal 五档决策比率删除（Proposal 移出 0.3），保留隐式反馈信号。
- **地域分支**：欧盟 IP 默认 opt-in（关）、非欧盟 opt-out（开）。
- **数据采集 tab**：PostHog opt-in + 自进化 toggle 两条独立开关。
- **可降级**：自进化埋点（§三-A）若 2 周窗口紧张可整体降级，0.3 至少保留 Sentry + PostHog 基础埋点（发布运维底线）。
- **红线**：绝不采集文献全文/PDF/笔记原文/对话原文/API Key/邮箱/用户名/含用户名路径。

## 验收标准

| # | 验收 | 优先级 |
|---|------|--------|
| T-1 | 手动触发崩溃 → Sentry Dashboard 可见含堆栈，且 payload 无邮箱/IP、路径用户名段已脱敏 | 必做 |
| T-2 | 走一遍检索/综述/登录 → PostHog 可见对应事件流 | 必做 |
| T-3 | 欧盟 IP 账号默认未上报、开启后才上报；非欧盟默认上报、关闭后停止 | 必做 |
| T-4 | 数据采集 tab 两开关解耦：关自进化不影响 PostHog | 必做 |
| T-5 | 自进化 5 类信号 schema 在仓库可查，每类独立、外部可还原字段范围 | 必做（自进化降级则免）|
| T-6 | 走 5 类信号场景各 1 次，自进化端点日志可见落库 | 必做（自进化降级则免）|

## Out of Scope（本 epic）

自动微调链路 / RAG 注入 / 模型权重更新（0.4/V1）；联邦学习 / 本地小模型；个性化推荐算法；自进化透明度 UI（本周事件查看 / 一键清空 / 首次任务流引导弹窗，0.4）；Proposal 决策信号采集（随 Proposal 移出）。

# Epic 4：数据所有权（导出 + 删账户）

## Problem Statement

GDPR 要求用户可携带数据（Art.20）与被遗忘（Art.17）。用户也需要确信"研究数据是我的、能带走、能删除"。

## Solution

**DO2**：一键导出全部本地研究数据为符合开放 JSON Schema 的 zip 包，ajv 校验通过——数据是行业可解析的标准格式而非私有 dump。**DO3**：一键删除账户，清空服务端身份 + 行为遥测数据，本地研究库（设备级）保留。

## User Stories

1. 作为用户，我想一键导出我全部本地研究数据为 zip，以便备份或带走我的数据。
2. 作为用户，我想导出的数据符合开放 JSON Schema 且通过 ajv 校验，以便数据是行业可解析标准格式、可被其他工具读取。
3. 作为用户，我想导出涵盖所有对象类型（papers/notes/evidence-sets/evidence-refs/citation-relations/reviews），以便数据完整。
4. 作为用户，我想在账户 tab 找到导出入口，以便集中管理我的数据。
5. 作为用户，我想一键删除我的账户，以便行使 GDPR 被遗忘权。
6. 作为用户，我想删除账户后服务端的身份与行为数据被清空，以便我的服务端足迹被移除。
7. 作为用户，我想删除账户后本地研究库保留，以便我仍保有我的研究资产。
8. 作为用户，我想删除账户前有明确二次确认与影响说明，以便不误操作。

## 关键产品决策

- **DO2 完整版**：0.3 产出 O1 开放 JSON Schema（从对象 TS interface 生成）；导出 zip + ajv 校验通过。这把 0.2 §二 O1 开放标准的产出拉进 0.3。
- **DO3**：删账户 = 清服务端身份 + 行为遥测；本地研究库设备级保留（不随账户删除）。
- **DO1（数据位置卡片）、DO4（本地优先叙事文案）已砍**，降级 0.4。
- 导出/删账户入口落在 Settings 账户 tab。

## 验收标准

| # | 验收 | 优先级 |
|---|------|--------|
| DO-2 | 点"导出我的数据" → 得 zip 包 → 用 ajv 校验通过 | 必做 |
| DO-3 | 触发删除账户 → 服务端用户记录 + 行为数据清空 → 本地研究库保留可见 | 必做 |
| DO-O1 | 对象 JSON Schema 在仓库 `schema/` 可查，覆盖全部导出对象类型 | 必做 |

## Out of Scope（本 epic）

DO1 数据位置可视化卡片（0.4）；DO4 本地优先叙事文案（0.4）；跨设备同步；导出格式的第三方互操作认证。

# Epic 5：版本更新

## Problem Statement

公开发布后需要可靠的更新分发，让用户及时拿到修复与新功能，且更新失败不能损坏当前可用版本。

## Solution

基于 electron-updater（已集成）：启动自动检查 + 手动检查入口 + 完整下载→安装→重启流程。macOS 必做；Windows 视 EV 签名 lead-time 决定（可降级到 0.4）。

## User Stories

1. 作为 macOS 用户，我想新版本发布后启动时收到更新提示，以便知道有新版本。
2. 作为用户，我想有手动检查更新的入口，以便主动查看。
3. 作为 macOS 用户，我想完整的下载→安装→重启→新版本生效流程，以便顺利升级。
4. 作为用户，我想更新失败（如断网）时当前版本仍正常使用，以便不被更新中断工作。
5. 作为 Windows 用户（若 EV 到位），我想同样的更新提示与流程。

## 关键产品决策

- macOS 必做（UP1/UP2/UP3）；Windows 可降级（UP1w/UP2w 依 EV 签名 lead-time）。
- 更新 feed 托管位置（自建 vs GitHub Releases）属实现细节，由实现侧定；产品需求为上述流程。

## 验收标准

| # | 验收 | 优先级 |
|---|------|--------|
| UP-1 | macOS 发布新版本 → 启动旧版本 → 收到更新提示 | 必做 |
| UP-2 | macOS 完整更新流程，版本号变更生效 | 必做 |
| UP-3 | 断网触发更新，现有版本不崩溃 | 必做 |
| UP-1w/2w | Windows 对应流程 | 可降级（依 EV）|

## Out of Scope（本 epic）

强制更新；增量/差分更新；Windows 自动更新（若 EV 延期则 0.4）。

# Epic 6：安全合规（GDPR MVP）

## Problem Statement

面向欧盟用户公开发布，需满足 GDPR 最小合规，并建立基本的传输/认证/运维安全，否则存在法律风险与信任缺失。

## Solution

GDPR MVP：Privacy Policy / ToS、DPA 签约、EU Representative 外包、欧盟用户 opt-in（见 Epic 3）、数据导出/删除（见 Epic 4）、跨境 SCC 披露（如适用）。安全：TLS 1.3、JWT + Refresh 轮转、Rate Limiting/CORS、Token safeStorage、Dependabot 阻断高危漏洞。

## User Stories

1. 作为用户，我想能查阅 Privacy Policy 和 ToS，以便了解数据如何被处理。
2. 作为用户，我想 Privacy Policy 明确说明 ASCI 服务端存什么（身份映射 + 行为遥测）、OPENSCI 是身份提供方、研究数据存本地，以便知情。
3. 作为欧盟用户，我想跨境传输有 SCC 披露（如适用），以便合规可查。
4. 作为用户，我想所有 API 流量 TLS 1.3 加密，以便无明文传输。
5. 作为用户，我想 API 有 Rate Limiting，以便服务稳定、防滥用。
6. 作为产品团队，我想 Dependabot 在 CI 阻断高危漏洞 PR，以便依赖安全。
7. 作为用户，我想能请求删除我的数据（链接 DO3），以便行使被遗忘权。

## 关键产品决策

- **GDPR MVP scope**：DPO 选定、正式 DPIA、律师起草级文档推迟到 0.4/V1 规模化触发（1k+ EU 用户或收费）。
- **Privacy Policy 须反映新架构**：ASCI 服务端仅身份映射 + 行为遥测、OPENSCI 为身份方、研究数据本地。
- **法人主体可用 placeholder**：不阻塞发布，发后 30-90 天内补主体字段。
- API 流量不做 Cert Pinning（桌面应用反模式）；update channel 可选 pinning。

## 验收标准

| # | 验收 | 优先级 |
|---|------|--------|
| SC-1 | Privacy Policy / ToS 可查，覆盖 GDPR 数据处理说明 + 新架构口径 | 必做 |
| SC-2 | 抓包确认 API 无明文传输（TLS 1.3） | 必做 |
| SC-3 | 压测触发 Rate Limit 返回 429 | 必做 |
| SC-4 | Dependabot 集成 CI，高危漏洞 PR 被阻断 | 必做 |
| SC-5 | 用户可请求删除数据（DO3 链路）；SCC 文本（如适用）在隐私政策可查 | 必做 |

## Out of Scope（本 epic）

DPO 选定 / 正式 DPIA / 律师级合规文档（0.4/V1）；法人主体最终确认（发后补）；服务端运维 SOP（§五-B，0.4/V1）。

# Epic 7：发布前置（lead-time checklist）

## Problem Statement

公开发布卡点多为审核/物流/合同周期问题（非工程量），不前置启动则 2 周代码窗口无法吸收，会阻塞或推迟发布。

## Solution

前置 lead-time 清单逐项盯到位：Apple/Windows 签名、邮件域、**新增 OPENSCI SSO 接口契约冻结 + 就绪时点**。各项有硬截止与降级评估触发点。

## User Stories

1. 作为发布负责人，我想 Apple Developer + macOS Notarization 就绪，以便 macOS 安装包不被 Gatekeeper 拦截。
2. 作为发布负责人，我想 Windows EV Code Signing 状态在 Week 1 末明确，以便决定 Windows 是否双平台首发（否则 → 0.4）。
3. 作为发布负责人，我想 OPENSCI SSO 的 OAuth/OIDC 接口契约冻结 + 就绪时点明确，以便账户 epic 不被并行建设的 OPENSCI 阻塞。
4. 作为发布负责人，我想确认 ORCID/Google OAuth client 归 OPENSCI（ASCI 免申请），以便不重复申请、减少 lead-time。
5. 作为发布负责人，我想邮件发件域（若 ASCI 需发产品通知邮件）SPF/DKIM/DMARC 就绪，以便邮件不进垃圾箱；若登录邮件归 OPENSCI 则 ASCI 免。
6. 作为发布负责人，我想各前置项有明确状态（已启动/已完成/不可达需降级）与硬截止，以便延误时及时触发降级评估。

## 关键产品决策

- **OPENSCI SSO 接口就绪是新增的关键前置**：OPENSCI 在 0.3 期间与 ASCI 并行建设（中等依赖风险），接口契约需尽早冻结。
- **ORCID/Google OAuth client 归 OPENSCI**，ASCI 免申请（相比 north-star 大幅减 lead-time）。
- **Windows EV 是双平台首发的决定性变量**：Week 1 末决策，未到位则 Windows 整体进 0.4、仅 macOS 首发。
- 邮件域：若登录类邮件全由 OPENSCI 处理，ASCI 可免；产品通知邮件视是否需要。

## 验收标准

| # | 验收 | 优先级 |
|---|------|--------|
| LT-1 | macOS Notarization 可签出可双击运行的安装包 | 必做 |
| LT-2 | Windows EV 状态在 Week 1 末决策：到位 → 双平台首发；未到位 → 触发 Windows → 0.4 降级 | 必做 |
| LT-3 | OPENSCI SSO 接口契约冻结，端到端登录回调跑通 | 必做 |
| LT-4 | 各前置项状态从"待盘点"转为明确结论并记录，延误同日触发降级评估 | 必做 |

## Out of Scope（本 epic）

ORCID/Google OAuth client 自申请（归 OPENSCI）；§五-B 运维 SOP；GitHub OAuth（已砍）。
