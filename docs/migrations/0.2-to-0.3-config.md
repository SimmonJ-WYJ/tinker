# 旧配置 → 0.3 迁移方案（0.2-to-0.3 Config Migration Plan）

> **状态**：草稿 · 待 review
> **审计标准**：0.2 §三-4 X4
> **关联 issue**：#240（E-6）
> **依赖**：E-4 (#231) 能力包概念 Spec · E-5 (#236) UI 概念稿

---

## 1. 概述

本文档定义 ASCI 从 0.2 升级到 0.3 时，所有用户配置的迁移映射。目标：**0.1/0.2 老用户升级到 0.3 不丢任何配置**。

### 迁移原则

1. **零数据丢失**：所有已有配置字段在 0.3 中保留或迁移，无静默删除
2. **向后兼容**：0.3 启动时自动读取 0.2 格式，无需用户手动操作
3. **渐进式迁移**：仅在用户首次打开 0.3 时执行一次迁移逻辑，写入 `_migrationVersion` 标记
4. **安全回退**：迁移前备份原文件为 `*.v2.bak`，迁移失败时可手动恢复

## 2. 存储文件映射

### 2.1 `~/.asci/` 目录结构变更

| 文件/目录 | 0.2 状态 | 0.3 目标 | 变更类型 |
|-----------|---------|---------|---------|
| `settings.json` | AppSettings 全部字段 | AppSettings + 新增 `dataCollectionOptIn` + `_migrationVersion` | **扩展** |
| `channels.json` | Provider API Key（AES-256-GCM） | 不动 | 不动 |
| `mcp.json` | 全局 MCP 服务器配置 | 不动（继续作为全局配置） | 不动 |
| `proxy-settings.json` | 代理配置（`ProxyConfig`：enabled / mode / manualUrl） | 不动 | 不动 |
| `user-profile.json` | 用户头像 + 显示名 | 不动 | 不动 |
| `agent-workspaces/{slug}/skills/` | Skill 文件系统 | 不动 | 不动 |
| `agent-workspaces/{slug}/skills-inactive/` | 禁用的 Skill | 不动 | 不动 |
| `agent-workspaces/{slug}/mcp.json` | 不存在 | **新增**（工作区级 MCP 覆写，可选） | **新增** |

| `reviews/` | 综述 HTML 文件 | 不动 | 不动 |

### 2.2 文件格式变更

`settings.json` 是唯一需要 schema 扩展的文件。其他文件（`channels.json`、`mcp.json`、`proxy-settings.json`、`user-profile.json`）的 schema 在 0.3 中不变。

### 3.5 Legacy / 待决策项

以下字段在 0.2 中仍在使用，0.3 的处置策略需在实现阶段确定。迁移脚本**保留原字段不删除**，确保不丢数据。

| 字段 | 0.2 现状 | 0.3 处置建议 | 说明 |
|------|---------|-------------|------|
| `agentWorkspaceId` | 活跃使用（7+ 处引用，用于工作区恢复/切换） | **保留**：继续作为最近工作区状态持久化；若 0.3 引入新的工作区状态管理机制，迁移到新字段后标记 legacy | 当前 `main.tsx`、`ProjectSwitcher.tsx` 等均依赖此字段 |
| `onboardingSpotlight` | 活跃使用（V2 多阶段引导状态机） | **保留**：0.3 若重新设计 onboarding，由新方案决定是否消费或重置；保留原字段不影响读取 | `onboarding-spotlight-service.ts` 管理完整状态机 |
| `onboardingChecklist` | DEPRECATED（类型为 `unknown`，已被 `onboardingSpotlight` 替代） | **保留**：仅为读取老数据兼容，0.3 UI 不再写入；待 0.4 清理 | `settings.ts` 中已标注 DEPRECATED |

> **安全原则**：所有 legacy 字段在迁移脚本中**不删除、不移动**，仅在 `_migrationVersion` 标记后由 0.3 新逻辑决定是否继续写入。避免实现阶段误删用户状态。

## 6. 新增项

### 6.1 数据采集 tab（0.3 §三-A）

```typescript
interface DataCollectionOptIn {
  posthogEnabled?: boolean
  selfEvolutionEnabled?: boolean
  optInTimestamp?: number
  region?: 'eu' | 'non-eu'
}
```

- 首次启动 0.3 时弹出同意对话框
- EU 用户默认全 `false`，非 EU 默认全 `true`
- 用户可随时在数据采集 tab 修改

### 6.2 工作区级 MCP 配置（可选）

```
~/.asci/agent-workspaces/{slug}/mcp.json

- 0.3 新增，允许工作区覆写全局 MCP 配置
- 首次升级时不自动创建（仅当用户在特定工作区添加 MCP 时创建）
- `composeMcpServers()` 合并全局 + 工作区配置

### 6.3 能力包存储

```

  └── {package-id}/

- 两个内置包（`asci.builtin.lit-search` / `asci.builtin.lit-review`）在首次启动时自动注册
- 不影响 `settings.json`

## 7. 升级路径走查

### 7.1 场景：0.2 老用户首次启动 0.3

```
用户双击打开 ASCI 0.3
   ↓
主进程启动 → 读取 ~/.asci/settings.json
   ↓
检查 _migrationVersion 字段
   ├─ 不存在（0.2 用户）→ 执行迁移
   └─ === 3（已迁移）→ 跳过
   ↓
执行迁移（settings.json）:
   1. 备份 settings.json → settings.v2.bak
   2. 读取全部现有字段（保留不动项 + 迁移项 + legacy 项）
   3. 初始化新增项（dataCollectionOptIn 默认值）
   4. 写入 _migrationVersion: 3
   5. 保存 settings.json
   ↓
非 settings.json 文件处理（不读取不改写，仅确认存在性）:
   - channels.json：原样保留，加密的 API Key 不触碰
   - mcp.json：全局配置原样保留；0.3 workspace-level MCP 是新增覆盖层，不自动搬迁
   - proxy-settings.json：原样保留（ProxyConfig schema 不变）
   - agent-workspaces/{slug}/skills/ 和 skills-inactive/：原样保留
   - user-profile.json：原样保留
   ↓
弹出数据采集同意对话框（首次）
   ↓
渲染器启动 → Settings 弹窗新 tab 结构生效
   ↓
左侧栏出现"配置"入口（Skill + 能力包板块）
   ↓
两个内置能力包自动注册到当前工作区
   ↓
完成。用户所有配置保留。
```

### 7.2 场景：0.1 老用户直接升级到 0.3

0.1 → 0.3 的 settings.json 字段是 0.2 的子集（0.1 没有的字段在 0.2 已用默认值初始化）。因此 0.1 → 0.3 走同一条迁移路径，无需特殊处理。

### 7.3 场景：全新安装 0.3

```
首次启动 → ~/.asci/ 不存在
   ↓
创建目录结构 + 初始化 settings.json（含 _migrationVersion: 3）
   ↓
弹出数据采集同意对话框
   ↓
正常启动
```

## 8. 迁移逻辑伪代码

```typescript
/**
 * 0.2 → 0.3 配置迁移
 * 在主进程启动时执行一次，仅处理 settings.json
 * 其他配置文件（channels / mcp / proxy / skills）无需迁移
 */
function migrateSettingsV2toV3(settingsPath: string): void {
  const raw = readJsonSync(settingsPath)

  // 已迁移则跳过
  if (raw._migrationVersion >= 3) return

  // 1. 备份
  copyFileSync(settingsPath, settingsPath.replace('.json', '.v2.bak'))

  // 2. 保留所有现有字段（不动项 + 迁移项 + legacy 项）
  //    agentWorkspaceId / onboardingSpotlight / onboardingChecklist
  //    全部原样保留，0.3 新逻辑决定是否继续写入

  // 3. 初始化新增项（不覆盖已有值）
  raw.dataCollectionOptIn ??= {
    posthogEnabled: false,   // 首次启动对话框决定
    selfEvolutionEnabled: false,
    optInTimestamp: undefined,
    region: undefined,       // 注册时推断
  }

  // 4. 写入版本标记
  raw._migrationVersion = 3

  // 5. 保存（原子写入：先写 .tmp 再 rename）
  writeJsonAtomicSync(settingsPath, raw)
}

/**
 * 非 settings.json 文件确认（仅日志，不改写）
 */
function verifyNonSettingsFiles(configDir: string): void {
  const files = ['channels.json', 'mcp.json', 'proxy-settings.json', 'user-profile.json']
  for (const file of files) {
    const exists = existsSync(join(configDir, file))
    console.log(`[迁移] ${file}: ${exists ? '存在，原样保留' : '不存在，跳过'}`)
  }
  // agent-workspaces/ 目录及其 skills/ 子目录原样保留
}
```

> **注意**：此伪代码仅描述逻辑，不在本 issue 实现。实现在 0.3 §三-C 阶段。

## 9. 边界情况处理

| 边界情况 | 处理策略 |
|---------|---------|
| `settings.json` 不存在 | 视为全新安装，跳过迁移，直接初始化 |
| `settings.json` 是空文件 | 视为全新安装 |
| `settings.json` 解析失败（JSON 损坏） | 备份为 `settings.corrupted.bak`，重新初始化 + 日志告警 |
| 字段类型不兼容（如 `archiveAfterDays` 从 number 变成 string） | 0.3 不改任何现有字段类型，不存在此问题 |
| `mcp.json` 不存在 | 正常（用户未配置自定义 MCP），内建 MCP 由 `resolveBuiltinMcpServers()` 运行时计算 |
| `skills/` 目录不存在 | 正常（工作区未初始化 Skill），0.3 按默认分类启用内置 Skill |
| 0.2 `agent` tab 的 URL hash 书签 | 0.3 中 `#agent` 重定向到 `#general`（Agent 运行时分区） |
| 多用户共享 `~/.asci/` | 不支持（单用户设计），迁移脚本不加文件锁 |
| 迁移执行到一半断电 | 原文件已备份为 `.v2.bak`；下次启动检测到 `_migrationVersion` 缺失重跑迁移 |
