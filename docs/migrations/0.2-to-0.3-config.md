# Legacy Configuration → 0.3 Migration Plan (0.2-to-0.3 Config Migration Plan)

> **Status**: draft · awaiting review
> **Audit criterion**: 0.2 §III-4 X4
> **Related issue**: #240 (E-6)
> **Dependencies**: E-4 (#231) capability-package concept spec · E-5 (#236) UI concepts

---

<a id="1-概述"></a>

## 1. Overview

Defines mappings for all user configuration when upgrading ASCI 0.2 to 0.3. Goal: **0.1/0.2 users upgrading to 0.3 lose no configuration**.

<a id="迁移原则"></a>

### Migration Principles

1. **Zero data loss**: preserve or migrate every existing field, no silent deletion.
2. **Backward compatibility**: 0.3 automatically reads 0.2 formats at startup, no manual user actions.
3. **Gradual migration**: execute once on first 0.3 launch, recording `_migrationVersion`.
4. **Safe rollback**: back up originals as `*.v2.bak` before migration for manual recovery on failure.

### 3.5 Legacy / Pending Decisions

| Field | 0.2 state | Recommended 0.3 handling | Description |
|------|---------|-------------|------|

## 7. Upgrade Walkthrough

<a id="71-场景02-老用户首次启动-03"></a>

### 7.1 Existing 0.2 User's First 0.3 Launch

The flow: open ASCI 0.3 → main reads settings → missing migration marker runs migration, ===3 skips → back up settings.v2.bak, retain all fields including legacy, initialize consent defaults, write marker 3, save → verify only existence of other files without reading/rewriting: encrypted channel keys untouched, global MCP unchanged with workspace override layer, proxy schema/Skills/inactive Skills/profile preserved → first consent dialog → renderer activates new tabs → sidebar Configuration (Skills + packages) → register both built-ins in current workspace → complete, all settings retained.

```
User double-clicks ASCI 0.3
   ↓
Main starts → reads ~/.asci/settings.json
   ↓
Check _migrationVersion
   ├─ Missing (0.2 user) → migrate
   └─ === 3 (already migrated) → skip
   ↓
Migrate settings.json:
   1. Back up settings.json → settings.v2.bak
   2. Read all existing fields (retain unchanged + moved + legacy fields)
   3. Initialize additions (dataCollectionOptIn defaults)
   4. Write _migrationVersion: 3
   5. Save settings.json
   ↓
Other files (existence checks only, no reads/rewrites):
   - channels.json: unchanged, encrypted API keys untouched
   - mcp.json: global configuration unchanged; new 0.3 workspace-level override, no automatic move
   - proxy-settings.json: unchanged (same ProxyConfig schema)
   - agent-workspaces/{slug}/skills/ and skills-inactive/: unchanged
   - user-profile.json: unchanged
   ↓
First data-collection consent dialog
   ↓
Renderer starts → new Settings modal tabs take effect
   ↓
Sidebar Configuration entry appears (Skills + capability packages)
   ↓
Register two built-in packages automatically in current workspace
   ↓
Complete. All user configuration retained.
```

## 8. Migration Pseudocode

Comments describe a one-time main-process settings-only migration, skipping marker >=3, backing up, preserving every field including agentWorkspaceId/onboardingSpotlight/onboardingChecklist, initializing new fields without overwrites (dialog decides consent, registration infers region), setting version, and atomic temporary-file/rename save. The verification helper logs existence without rewrites and preserves workspace/skills directories; Chinese log literals mean “migration,” “exists, preserved,” and “absent, skipped.”

```typescript
/**
 * 0.2 → 0.3 配置迁移
 * 在主进程启动时执行一次，仅处理 settings.json
 * 其他配置文件（channels / mcp / proxy / skills）无需迁移
 */
function migrateSettingsV2toV3(settingsPath: string): void {
  const raw = readJsonSync(settingsPath)

  // 已迁移则跳过
  if (raw._migrationVersion >= 3) return

  // 1. 备份
  copyFileSync(settingsPath, settingsPath.replace('.json', '.v2.bak'))

  // 2. 保留所有现有字段（不动项 + 迁移项 + legacy 项）
  //    agentWorkspaceId / onboardingSpotlight / onboardingChecklist
  //    全部原样保留，0.3 新逻辑决定是否继续写入

  // 3. 初始化新增项（不覆盖已有值）
  raw.dataCollectionOptIn ??= {
    posthogEnabled: false,   // 首次启动对话框决定
    selfEvolutionEnabled: false,
    optInTimestamp: undefined,
    region: undefined,       // 注册时推断
  }

  // 4. 写入版本标记
  raw._migrationVersion = 3

  // 5. 保存（原子写入：先写 .tmp 再 rename）
  writeJsonAtomicSync(settingsPath, raw)
}

/**
 * 非 settings.json 文件确认（仅日志，不改写）
 */
function verifyNonSettingsFiles(configDir: string): void {
  const files = ['channels.json', 'mcp.json', 'proxy-settings.json', 'user-profile.json']
  for (const file of files) {
    const exists = existsSync(join(configDir, file))
    console.log(`[迁移] ${file}: ${exists ? '存在，原样保留' : '不存在，跳过'}`)
  }
  // agent-workspaces/ 目录及其 skills/ 子目录原样保留
}
```

> **Note**: pseudocode describes logic only; this issue does not implement it. Implementation belongs to 0.3 §III-C.

<a id="9-边界情况处理"></a>

## 9. Edge Cases

| Edge case | Handling |
|---------|---------|
| Missing `settings.json` | Fresh install, skip migration and initialize |
| Empty `settings.json` | Fresh install |
| Corrupt JSON | Back up `settings.corrupted.bak`, initialize + warning log |
| Incompatible type (e.g. `archiveAfterDays` number→string) | 0.3 changes no existing types, so not applicable |
| Missing `mcp.json` | Normal, no custom MCP; built-ins computed by `resolveBuiltinMcpServers()` |
| Missing `skills/` | Normal, workspace Skills uninitialized; 0.3 enables built-ins by default categories |
| Old agent-tab URL bookmark | Redirect `#agent` to `#general` runtime section |
| Multiple users sharing `~/.asci/` | Unsupported single-user design, no migration file lock |
| Power loss mid-migration | Original backed up as `.v2.bak`; rerun on next launch if `_migrationVersion` is missing |
