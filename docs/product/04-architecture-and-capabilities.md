# 技术方向与能力核实

## 沿用现有架构

当前目录是独立新项目；继续使用 Rust 核心 + Tauri 桌面壳 + React/TypeScript 界面，不为文档重建工程或更换技术栈。

| 当前单元 | 现状 | 计划职责 |
|---|---|---|
| `core/` | 内存会话与固定演示回复 | 任务、会话、尝试状态及恢复规则；尽量保持可独立测试 |
| `src-tauri/` | session/save_secret 两类命令、macOS 钥匙串写入 | 窄 IPC、渠道网络适配、安全存储、本地数据及受授权工具执行 |
| `src/` | React 界面与浏览器内存 fallback | 用户选择、进度、授权、错误与产物呈现；不保存明文密钥或直接执行工具 |
| 锁文件及 `docs/DEPENDENCIES.md` | 依赖版本和来源记录 | 变更依赖时更新许可与来源；保留上游署名与条款 |

计划的数据链路：界面提交任务及选择 → Rust 校验权限与预算范围 → 从系统安全存储读取密钥 → 调用选定渠道适配器 → 增量事件回传 → 本地保存状态、用量与产物引用。失败和取消通过同一状态模型表达，不用“成功但无结果”替代错误。

当前浏览器 fallback 与 Rust 演示是两个实现；未来需避免把浏览器模拟通过当成桌面真实通过。新建任务模型时兼容现有渠道草稿隔离，不在 UI 切换过程中暗中丢弃旧状态。

## 计划的数据与能力模型

- Channel：名称、协议、端点、密钥引用、能力验证日期；不把密钥写入普通配置。
- ModelCapability：渠道模型标识、输入/输出模态、工具/流式/编辑/异步支持及限制；所有字段有证据或明确未知。
- Task / Step / Attempt：独立任务 ID、步骤依赖、每次请求渠道与模型、授权范围、状态及错误；渠道变更不创建割裂任务。Attempt 用于区分重试与原请求。
- Artifact：版本、媒体类型、位置、来源步骤、输入引用及内容校验值；生成新版本不覆盖用户原件。
- Usage / Cost：上游原始用量、价格来源与时间、估算、实收/未知状态及币种；避免把不同计价单位直接相加。
- Grant：用户授予的工具、路径、网络目标、费用范围与有效期；生成内容不能修改 Grant。

建议状态：排队 → 等待授权 → 执行中 → 成功/失败/已取消/结果未知。未知结果先查询上游（如果支持）；没有查询能力时说明重复计费风险，由用户决定重试。是否支持幂等键取决于接口，不假设所有渠道具备。

## 如何把“待验证”改为“可用”

1. 保存供应商官方来源、访问日期、适用账户/区域/版本和使用限制，脱敏记录。宣传页只能证明宣传内容，不能代替接口测试。
2. 记录最小真实请求/响应（密钥与敏感内容脱敏）、输出样例、延迟、usage、费用来源、错误格式及取消语义。付费测试先取得具体预算授权。
3. 验证断网、限流、不支持模型、部分输出和未知结果；确定能否重试、查询或编辑。无法验证则继续标未知。
4. 将实际限制映射到 PRD，完成桌面闭环；使用“已验证：具体能力 + 日期 + 环境”，不把一个接口成功推广到整个渠道。
5. 接口/模型/价格变化时重新核实。不可用时降为待验证或禁用，禁止静默切到另一供应商。

记录模板：能力 / 渠道与模型 ID / 来源 URL 与日期 / 账户条件（脱敏） / 请求样例与输出路径 / 费用口径 / 限制 / 失败和取消结果 / 测试人 / 结论 / 下次复核触发条件。目前没有填入供应商数据，避免虚构支持列表或价格。

## 存储、安全与版权约束

持久化计划使用可迁移的本地结构并执行原子写入/备份；具体文件格式或数据库在实现前选择，不在本轮引入新依赖。日志、导出、错误与截图均脱敏。敏感上下文仅发往用户已选择且授权的渠道，不默认云同步。

工具执行边界见 PRD。文件写入应有版本或可回滚副本；网络请求、异步远端作业与已发生计费通常不能本地回滚，必须在 UI 中准确说明实际状态。自动失败恢复不能被设计为无限付费重试。

旧 ASCI 项目代码、素材和许可证不在本轮复制或变更范围。新增依赖/资产分别记录来源、许可与分发要求。模型输出、商标和第三方产品集成的使用权需要按相应来源核实，独立重建不自动解决权利问题。
