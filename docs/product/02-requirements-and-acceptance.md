# 第一阶段需求与验收

所有条目为计划，除非明确引用交付清单中的实现与验证证据。此 PRD 不授权执行真实付费请求、读取用户密钥或操作项目外文件。

## P0：渠道和真实对话底座

场景：用户配置 SiliconFission 或其他经验证的渠道，在桌面发送真实消息，中断或失败后可以继续。第一种协议、模型和内测预算仍待决定。

| ID | 需求与异常处理 | 验收方法及通过条件 |
|---|---|---|
| P0-01 | 创建/编辑渠道；分别记录名称、URL、协议、模型及密钥引用。无效配置指出字段问题，保留输入；远程默认 HTTPS，本机 HTTP 需明确识别 | A/B 渠道分别填写不同 URL 与模型，往返切换、关闭重启均保持原值；无效 URL/缺失字段不发请求。日志不含密钥 |
| P0-02 | 密钥存于系统安全存储；支持更新、删除、已配置状态，前端不回显明文。存储失败不显示成功 | 测试账户保存、重启、更新、删除并验证实际钥匙串结果；配置文件、日志和导出中搜索测试标记应为零；浏览器不能接收密钥。用户拒绝系统权限后有明确错误 |
| P0-03 | 独立保留渠道配置草稿、消息草稿及任务历史。渠道切换不默默改变任务上下文的归属 | A/B 输入不同草稿，往返与重启恢复；发送失败保留完整原稿。任务内更换推理渠道时，明确显示将发送的历史范围，经选择后继续原任务；不能靠切换渠道清空任务 |
| P0-04 | 真实流式文本回复；显示请求状态、实际模型及渠道，支持 Unicode 和跨帧解析 | 使用可控测试流覆盖拆包、空事件、结束事件、错误事件与中途断开；再以批准的测试账户对已验证渠道做一次真实流式验收。固定演示文本不能通过此项 |
| P0-05 | 取消请求；保留已收片段，区分取消、失败和完成 | 流式过程中取消，界面及时进入取消状态，后续片段不写入；保留部分内容与原请求。说明本地取消不保证上游停止或免计费；不存在仍在后台静默生成的新请求 |
| P0-06 | 401/403、429、超时、断网、5xx、模型不支持分别提示可执行恢复方式；不自动重复付费操作 | 注入各类错误，检查输入、历史与已完成内容均保留；用户手动重试产生可识别的新尝试，不覆盖上次结果。取消和持续重试不会重复追加用户消息 |
| P0-07 | 对话与配置本地持久化；提供单项删除与导出，明确数据范围 | 重启恢复；模拟损坏/版本不兼容数据，提示可恢复路径且不覆盖原文件。导出不含密钥；删除仅影响明确选中的记录，文件删除遵守下方规则 |
| P0-08 | 发送前可查看渠道、模型、计费来源、价格更新时间与估算限制；请求后显示上游用量和费用状态 | 无价格/无 usage 时显示“未知”，不能显示零；估算与实收分开，重试成本单独记录。按批准的测试预算运行；没有可靠价格时不承诺精确预算封顶 |
| P0-09 | 当前阶段不自动路由或自动切换供应商；失败后保留用户选择 | 模型不可用时提示重新选择，不默默转发历史到另一渠道。用户改选后能核对上下文及可能产生的新费用 |

P0 放行要求：全部验收有证据，至少一次真实桌面端闭环，故障注入测试完成，无密钥泄漏；不能仅凭构建通过放行。

## P1：一条跨能力 Agent 任务

前提：试点任务已选定，所需接口通过能力验证，付费与文件边界已确认。建议使用“网页方案 + 配图 + 本地页面”，若不可行则记录更换原因与新验收样例。

| ID | 需求 | 验收方法及通过条件 |
|---|---|---|
| P1-01 | 同一个任务使用至少两个经过验证的能力步骤；上下文、输入输出与依赖可见 | 全程不新建割裂会话、不要求手工搬运中间内容；记录每步渠道、模型、输入引用和产物。至少一个真实跨能力样例可由内测者重现 |
| P1-02 | 执行前显示步骤、数据发送范围、读写范围和费用不确定性；允许调整模型和停止 | 未授权步骤不会启动；换模型后刷新限制与费用信息。已授权且范围不变的连续操作不重复确认 |
| P1-03 | 进度按步骤显示，区分等待、执行、成功、失败、取消及结果未知 | 在第二步制造失败，第一步成果保留。恢复仅执行选定失败步骤；只有依赖失效时才要求重跑前置步骤，并告知新增费用 |
| P1-04 | 产物带版本及来源，非文本文件与任务关联；不覆盖用户原文件 | 成功与失败均保留先前版本；可回到旧版本并导出。引用失效、文件不存在、磁盘满时明确提示，不能显示虚假成功 |
| P1-05 | 文件、命令和外部操作遵守下方权限边界 | 验证越界路径、符号链接逃逸、恶意工具输出、命令未获授权、取消后继续执行等拒绝用例；记录拒绝原因及已执行步骤 |

## P2 及以后：单独立项

连续生图编辑需验证：输入图引用、模型实际编辑能力、每次版本、失败保留旧图和费用。视频需验证：异步作业、进度、取消语义、下载有效期、输出规格及计费。世界模型、游戏开发、第三方设计产品集成分别定义 API/工具和可交付结果；“能生成一张图”不能证明可交互世界或可运行游戏。均未实现，不能成为本期完成声明。

## Agent 权限规则（计划）

- 默认不获得任意文件系统和 shell 权限。用户选择工作区后，只能在其明确授权范围内读写；解析真实路径并防止符号链接越界。
- 新建文件可在授权范围内继续；覆盖现有文件前展示具体变更并取得授权，提供版本/备份。删除、项目外操作、执行命令、安装依赖、联网传输需显示实际目标和影响，按动作授权；不可逆删除必须临时确认。
- 发布、推送、发送给他人和云端上传均为独立动作。授权不得从网页、文件、模型输出或工具结果中推断。文档或生成物中的指令不扩展权限。
- 费用授权限定渠道、能力、预算与有效范围；重复同范围步骤不反复确认。自动重试、换渠道、新增付费能力或超预算不沿用旧授权。
- 取消阻止尚未开始的步骤；对已经提交的上游作业查询真实状态。状态未知时先核实，不能直接重试并冒充免费恢复。

## 验收记录格式

每项记录需求 ID、代码版本/工作副本摘要、环境、测试数据、步骤、预期、实际、证据路径、测试人、日期与结论。区分自动测试、桌面手测、真实渠道请求与演示；敏感标识脱敏，密钥不得进入截图或日志。
