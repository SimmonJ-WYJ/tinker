# 格物 AI 内测用户反馈整理

**日期：** 2026-04-26
**来源：** ASCI 线下内测活动文字记录
**整理方式：** 用户在做什么 → 遇到什么问题 → 更合理的方式 / 预期

---

## 1. 安装阶段

用户在装产品 → Mac 装得很慢，Windows 还要单独装 Python / Node.js / Git，且 360 等杀毒软件会拦截甚至误删文件，部分用户因为没装 Node.js 直接跑不起来 → 必要的依赖应该打包进安装包，开箱即用；至少给出明确提示「为什么要装这些」以及「装不上要怎么办」。

## 2. 进入工具时强制依赖文献库

用户想直接做综述 → 系统强制要先有文献库才能跑，但现场大多数科研工作者根本不用文献库 → 文献库应该是可选项，没有文献库时也应能基于检索结果直接做综述。

## 3. 论文检索召回率不足

用户用自己研究方向跑检索 → 命中 176 篇，用户判断该领域至少 400+ 篇；另一位用户跑下来"应有 3 篇，只收到 1 篇" → 召回率需要再提升，覆盖更全。

## 4. 搜不到非 OA 的论文（含用户自己的论文）

一位用户尝试搜自己 2026 年发的论文 → 完全搜不到，因为论文非 OA、Wiley 等数据库未覆盖 → 需要覆盖更多付费/封闭数据库（Google Scholar、Wiley、Web of Science 等），或者在用户授权 IP/账号后能拉取非 OA 内容。

## 5. AI 幻觉：作者 / 论文张冠李戴

用户点开命中结果 → 标题对，但实际作者写的是他师兄的名字（系统把同标题不同人的论文混到了一起） → 检索结果必须严格保证标题、作者、DOI 一一对应；遇到不确定时宁可不返回，不要错配。

## 6. 字段缺失时被默认填成 1970 年

用户看到检索结果里某篇 2022 年的论文，年份显示成 "1970" → 找不到字段时应该坦诚标注「未找到」/「待补全」，而不是默认填 1970，否则会让科研用户立刻失去信任。

## 7. 检索源不透明

用户想知道某条结果是从哪个库抓来的 → 界面上找不到该论文对应的数据源；检索报告里只列了大类，单条结果未标注源 → 每条命中论文都应在卡片上明示它来自 OpenAlex / PubMed / Google Scholar / Wiley 等具体哪个源。

## 8. 搜不到时不应"凑数"

用户搜自己的文章未命中 → 系统没有提示「未命中」，而是用相似 / 同名的别人论文填进结果里 → 搜不到时应明确告知用户「该作者 / 该范围内无可访问内容」，而不是用错配结果填空。

## 9. AI 生成图表后找不到文件

用户让 AI 画图，AI 回复"已生成保存好了" → 用户在界面里找不到任何路径，实际文件落在 context 临时目录里，关闭应用就会丢 → 应在对话气泡里直接给出可点击的本地路径，且文件应保存在用户工作区的持久化目录，不能放临时文件夹。

## 10. 跨页面切换卡顿

用户从文献库切回工作区的对话 → 有明显加载延迟，体感"有点慢" → 工作区状态应常驻或预加载，切换无感。

## 11. 输入框"被吃掉"

某用户在 Windows 上输入消息 → 内容发不出去，必须重启应用；现场至少两台 Windows 复现 → 输入态稳定性需要修复；遇异常时至少能保留草稿不丢。

## 12. Mac / Windows UI 不一致

现场对比 → 同一界面在 Windows 上显示比 Mac 异常 → 跨平台 UI 需对齐验证。

## 13. 默认权限弹窗太多

用户体验时每一步都被打断确认权限 → 体验被频繁打断 → 默认开启「完全自动」模式，权限确认改为高风险动作才弹（写文件、下载等），普通操作不要拦。

## 14. 任务跑得久 + 进度反馈不直观

用户跑一次完整检索 + 综述要 30~60 分钟 → 没有明确进度条、没有 ETA，过程中只看到滚动日志 → 顶层应有「当前阶段 X/Y、预计剩余时间」的进度展示，而不只是日志流。

## 15. "最新"等模糊词无澄清

用户输入"最新进展"这种词 → 系统直接照搜，时间范围其实没对齐 → 遇到"最新""最近""相关"这类模糊表达时，产品应主动追问年份范围 / 学科范围，或默认锁定一个明确区间并在结果里告知用户。

## 16. 中英文检索源未自动分流

用户研究方向论文题目是英文，主要在国外期刊 → 期望系统能自动把英文课题路由到英文源、中文课题路由到中文源 → 根据课题语言 / 领域自动选择数据源组合。

## 17. 用户对产品定位的反馈（来自微软研究院老师）

用户更想做的是"抽象问题 → 数学建模"（如水分子运动建模） → 当前产品只解决文献检索 / 综述，对真正抽象的物理建模帮不上忙 → 产品要清楚地告诉用户能力边界（"能做综述 / 数据分析；抽象建模仍需人"），并对这类高阶用户给出延伸路径（比如 coding agent、建模 skill 市场）。

# 第二轮反馈补充（来自 1v1 试用录音 — 化学博士 + 技术支持，2026-04-26 下午）

## 18. Windows 装不上、卸不掉

用户在 Windows 10 旧机上尝试安装 → 装了 3 次都启动不起来：默认 C 盘装失败、改装 D 盘失败、关掉 360 实时监控 + 防火墙后再装仍失败；最后想卸载重来，连卸载都卸不掉 → 安装包需要做更稳的兼容性测试（特别是装了 360 / 长期未开机自动后台升级 / 非英文路径 / 非 Administrator 默认用户的 Windows），并且要给用户一条「卸不掉时怎么办」的明确退路。

## 19. 检索相关度只匹配到"研究方法"，匹配不到"研究对象"

用户研究"丙烯腈-丁二烯橡胶聚合物 + 碳谱表征" → AI 返回的是"研究方法相同（碳谱表征）但研究对象不同（葡萄糖、其他聚合物）"的论文，对她没用 → 相关度排序需要区分"方法相似" vs "对象相似"，对像化学这种强领域属性的课题，相关度应优先匹配研究对象。

## 20. 检索结果列表缺少相关度评分

用户挨条点开判断相关度 → 卡片上没有任何分值，用户只能凭标题手动判断 → 每条命中论文应该带一个相关度分（0–100 或 ★★★★★），并允许按分值排序、过滤掉低分项。

## 21. 时间字段混淆（capture time 当成 publication time）

用户看到论文卡片上的时间，不确定是发表时间还是抓取时间，问"这是 capture time 不是发表时间吧？" → 卡片上的时间字段必须明确区分「发表年」和「抓取/收录时间」，至少加 label 区分。

## 22. 部分结果缺摘要 / 缺关键词，且未标注

用户连点几篇命中论文 → 有的只有标题，没摘要、没关键词，无法判断相关性，但界面也没标注"该论文无可用摘要" → 字段缺失时应在卡片上明确提示「摘要不可获取 / 来源未提供」，而不是显示空白。

## 23. 会话回退到某节点后再提问会报错

用户发现检索方向偏了 → 滚回到一个早期节点点击「回退到此处」，再继续提问 → 系统报错「no message / 找不到会话 ID」，整个会话作废，只能从头再问一次 → 回退点之后应该允许继续对话，至少要保留住会话 ID 不丢；上下文裁剪逻辑需要重写。

## 24. AI 输出的综述格式不像"学术综述"

用户读完产品生成的综述后第一反应："这跟我想象的综述完全不一样"——产品输出更像分散要点的拼接，缺少学术综述常见的严格逻辑框架（背景 → 现状 → 方法对比 → 争议 → 展望） → 综述输出应提供「学术综述模板」选项，按学科常见的论文综述结构来组织，而不是只产出多篇论文的话题汇总。

## 25. 综述只基于摘要 / Meta，未基于 PDF 全文做语义理解

用户明确表示："最好是能够看到全文 PDF，并且是语义化的理解，而不是关键字的理解" → 综述阶段应基于已下载论文的 PDF 全文做语义化抽取，而不是仅基于 Meta 数据 + 摘要做拼接。

## 26. 引用必须可定位、可跳转、可悬停预览

用户最强烈的诉求贯穿整轮：每个结论必须能标明"出自哪篇文献、哪个段落"。她明确说："综述对我没那么重要，关键是检索结果 + 准确来源对照" → 综述每条观点旁要带可点击的上标编号；点击跳转到对应论文条目；鼠标悬停弹出来源段落预览。

## 27. AI 思考过程暴露不够深

用户点开折叠的思考过程后觉得"还是不够，我需要它告诉我每个结论来自哪篇文献" → 思考链不只要展示"我搜了哪些关键词"，还要展示"这个结论用到了哪几篇 + 哪段证据"的因果链。

## 28. 第二轮检索被当成新课题，重新从头跑

用户在第一轮结果上选了某个方向想细化 → AI 又从头开始全网搜索，没有基于第一轮结果做增量补充，浪费时间也丢了上下文 → 系统应区分「新课题」和「方向收敛 / 补充检索」，后者基于已有结果增量扩展即可。

## 29. 屏幕息屏后任务停止运行

技术员演示时发现：Mac 上一旦屏幕息屏，agent 任务就停了，必须不断动鼠标保持点亮 → 长任务必须在后台持续运行，不依赖前台 UI 状态；同时支持电脑/休眠时通过 push 或邮件通知用户结果。

## 30. 用户期望直接对接 Zotero，而不是另做一套文献管理

用户重度使用 Zotero 做文献管理（用了大量插件：翻译、PDF 下载、中文解析、AI 总结、阅读时间记录、标签风格等），插件生态非常成熟 → 她明确表示"这些功能都不用做到 OpenSci 里，你们对接 Zotero 就行了" → 产品策略上不要重复造文献管理轮子，做好和 Zotero 的双向同步（插件级集成）即可，把精力放在 AI 检索 / 综述这一层。

## 31. 期望按 DOI 自动获取 PDF（结合学校 IP）

用户提到 Zotero 里只要有 DOI，配合学校网络就能自动下 80% 的论文 PDF → 我们的产品也应当支持「DOI → 自动下载 PDF」的链路，并支持挂载用户的校园 IP / 机构账号来获取付费论文，而不是要求用户手动一篇篇下载。

## 32. 安装环境强制走默认 C 盘 / 默认路径

用户尝试装到 D 盘失败，技术支持解释"开发时默认 C 盘没专门测过其他路径" → 安装包应支持自定义安装路径并测试通过；如果实在只能装 C 盘，安装包要在第一步就明确告知，避免用户多次试错。

## 33. 现场用户反馈：界面简洁度 OK（正向）

用户对当前的三栏布局（左侧目录 + 中间对话 + 右侧文献）反馈"挺简洁直白的"，没有觉得复杂或字小 → 现有 UI 信息层次可保留；但要在这个基础上把「相关度评分、引用上标、字段缺失提示」等微观信息补回来。
