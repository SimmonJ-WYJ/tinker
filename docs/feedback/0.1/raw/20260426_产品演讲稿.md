## 第一步：视频播放前，约 2-3 分钟

  各位老师，今天我们演示的是 ASCI Alpha。

  这一版我们没有先做一个“大而全”的科研助手。因为科研工作太复
  杂，如果一开始就承诺什么都能做，最后很容易变成一个看起来很
  强、但在关键环节不够可靠的通用聊天工具。

  所以 Alpha 阶段，我们先聚焦两个最基础、也最高频的科研场景：
  论文检索和文献综述。

  为什么是这两个场景？

  因为几乎每一个科研问题，最后都会回到两个动作：第一，能不能把
  相关文献找全、找准；第二，能不能在已有研究中快速看清结构、脉
  络和空白。

  但这两件事在实际工作中并不简单。

  首先，检索不是输入几个关键词然后等待结果。一个研究问题往往有
  很多种表达方式：同义词、缩写和全称、上下位概念、交叉学科术
  语、不同数据库里的表达习惯。关键词怎么扩展，哪些词该保留，哪
  些词会带来噪音，如何在召回率和相关性之间做平衡，这些都非常依
  赖经验。

  其次，今天很多 AI 工具已经能生成“看起来像综述”的内容，但科研
  人员真正关心的问题是：它依据了哪些文献？为什么这样判断相关
  性？为什么这样组织综述结构？哪些结论有明确来源，哪些只是模型
  推断？

  如果这些过程不可见，结果再流畅，也很难真正进入科研工作流。

  所以 ASCI Alpha 的目标很明确：不是替代科研判断，而是先把检索
  和综述这两个入口场景做得更透明、更可追溯、更适合科研人员使
  用。

  接下来这段 5 分钟的视频，会展示 ASCI 如何从一个研究问题出
  发，辅助完成关键词扩展、论文检索、相关性判断和初步综述生成。

## 第三步：演示后的总结，约 3-4 分钟

  刚才大家看到的是 ASCI Alpha 当前最核心的两个能力：围绕研究问
  题进行文献检索，以及基于检索结果生成可追溯的综述内容。

  但我们对 ASCI 的定位，不只是一个“论文搜索加总结工具”。

  我们真正想做的是一个面向科研任务的 Agent 基座。也就是说，
  ASCI 未来应该能够通过不同的工具、数据源、MCP 服务和 Skill，
  不断扩展它能处理的科研场景。也希望后续能和 OPENSCI 社区一
  起，在这个基座上共建更多面向真实科研流程的 Agent。

  接下来我们会重点推进三个方向。

  第一，是反黑盒。

  科研场景里，用户需要的不只是一个答案，而是一个可以理解、可以
  检查、可以干预的过程。

  比如系统扩展了哪些关键词，调用了哪些检索源，为什么认为某篇论
  文高度相关，最终综述主要依据了哪些材料，这些信息不应该长期藏
  在系统内部。

  我们希望 ASCI 的输出不是“相信我，这是答案”，而是“这是我的工
  作过程，你可以检查，也可以修改”。

  第二，是面向课题的记忆系统。

  科研不是一次性任务。同一个课题会反复检索、反复补充文献、反复
  调整问题、反复生成材料。

  所以 ASCI 的记忆系统，不会只停留在“记住聊天记录”。我们更关心
  的是围绕课题沉淀持续上下文：研究主题、术语偏好、历史检索结
  果、已有文献基础、用户关注的问题，以及阶段性的研究目标。

  只有具备这种课题级记忆，ASCI 才能从一次性工具，逐渐变成一个
  可以长期协作的科研系统。

  第三，是更深层的科研任务形态。

  Alpha 阶段我们先用对话式交互承载检索和综述，因为这是最自然、
  最容易上手的入口。

  但我们并不认为所有科研任务都适合只靠聊天完成。比如数据分析、
  实验设计、论文结构规划、研究方案比较，很多时候需要表格、流程
  图、可视化面板、可编辑的任务链，甚至需要 Agent 在后台持续执
  行。

  所以未来 ASCI 会保留对话作为入口，但不会把对话当成全部。不同
  科研任务，应该有不同的交互形态。

  最后，我想用一句话总结 ASCI Alpha：

  我们不是要让 AI 直接替科研人员下结论，而是希望让 AI 参与科研
  工作的过程，并且让这个过程足够透明、可追溯、可协作。

  如果各位正在做文献密集型研究，或者对科研 Agent、开放科研工具
  链、MCP 和 Skill 共建感兴趣，我们非常希望后续和大家持续交
  流。
