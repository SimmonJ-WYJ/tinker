# ASCI 对话流（Conversation Flow）

ASCI 桌面应用里 Agent 与用户对话的可视化区域。本文件记录"对话流"这一领域的统一语言，
供产品与工程在讨论会话渲染、执行过程展示时对齐术语。

## Language

**回合 / Turn**:
两次用户输入之间，Agent 产出的一段连续内容（可含多条 assistant 消息）。
_Avoid_: 消息组、message group（实现层用语，不在产品讨论中使用）

**过程块 / Process Block**:
Agent 在抵达最终回答前的中间步骤——即"思考（thinking）"块与"工具调用（tool call）"块。
_Avoid_: 中间消息、step（单说 step 时含义不清）

**最终回答 / Final Answer**:
Agent 面向用户的文字输出（text 块）。是用户真正关心的"结论"，始终一级可见、不被折叠。
_Avoid_: 文本块、text block（实现层用语）

**执行步骤组 / Execution Step Group**:
一段连续（≥2 个）过程块折叠而成的、对话流一级只占一行的可展开父集。
折叠时：运行中显示当前步（带转圈），完成后显示"已执行 N 步"；有步骤失败则显示报错徽标"⚠ 执行 N 步·M 步失败"（不自动展开）。
默认折叠，点击展开按原样式逐条看详情。
**单步退化**：若一段过程只有 1 个步骤，不包组，直接显示该过程块本身（保留具体工具名）。
_Avoid_: 父集（口语简称，正式文档用"执行步骤组"）、TodoBoard（那是另一个已存在的概念）

**队友 / Teammate（scenario sub-agent）**:
主 Agent 通过 `Task`/`Agent` 工具派发的子 Agent（如狐尼克、鹰尼克）。
每个队友的过程块单独成一个 **执行步骤组**，折叠行带队友名徽标（⊙ 名字·执行 N 步）。
_Avoid_: 子代理、subagent（口语可用，徽标统一用昵称）

**TodoBoard（任务进度卡）**:
Agent 的实时待办清单，由 `TodoWrite`/`TaskCreate`/`TaskUpdate` 工具驱动，渲染成一张进度卡片。
**与执行步骤组无关**——它是状态看板而非"待隐藏的过程"。
_Avoid_: 把它和 Task/Agent 派发（队友）混为一谈——二者都带"Task"字样但语义不同。

## Relationships

- 一个 **回合** 由若干 **过程块** 和 **最终回答** 交替组成
- 连续（≥2）的 **过程块** 折叠成一个 **执行步骤组**；**最终回答** 切断分组
- **说话人切换**（主 Agent ↔ 队友、队友A ↔ 队友B）也切断分组：每个 **队友** 自成一组
- **TodoBoard** 作为一级可见卡片，同样切断分组（组 → TodoBoard → 组）
- 因此对话流一级呈现：`最终回答 → 执行步骤组（一行）→ 最终回答 → 执行步骤组 → …`

## Example dialogue

> **PM：** 一个回合里 Agent 想了一下、查了三个工具、然后回答，对话流上看到什么？
> **工程：** 一个 **执行步骤组**（一行"执行 3 步"）+ 下面的 **最终回答**。想看过程点开那一行。
> **PM：** 如果中间它先回了半句话再继续查呢？
> **工程：** 那半句 **最终回答** 切断分组，变成：组 → 文字 → 新的组 → 文字。
> **PM：** 它派了狐尼克和鹰尼克干活呢？
> **工程：** 主 Agent 一组，狐尼克一组（⊙ 狐尼克·执行 6 步），鹰尼克一组，各自折叠。

## Flagged ambiguities

- "执行步骤"既可指单个过程块，也可指折叠后的组——已区分：单个叫 **过程块**，折叠后的父集叫 **执行步骤组**。
- "Task"歧义：`Task`/`Agent` = 派发 **队友**；`TaskCreate`/`TaskUpdate`/`TodoWrite` = **TodoBoard** 待办清单。二者无关。
- 单个过程块不成组（**单步退化**）——避免出现无意义的"执行 1 步"。

# 证据集与笔记（Evidence Set & Note）

记录"证据集 / 笔记 / 证据"领域的统一语言，供产品与工程在讨论文献阅读、综述溯源、知识沉淀时对齐。

> **0.4 P2 正在重定义"证据集"**（grill 会话 2026-06-01）：从"一条笔记的证据"(1:1) 升级为"研究主题容器"(1:N)，最终形态待科研场景需求探索裁决。下文 Language 用【当前】= v0.2 已实现、【0.4 目标】= 重定义方向 标注。

## Language

**证据集 / Evidence Set**:
【当前】一条**笔记**加它引用的若干**证据**，与笔记一对一强绑。
【0.4 目标】一个**研究主题的容器**：可容纳多条笔记 + 多个证据 + 标签 + 时间戳，是用户组织科研材料的一等单元；一条笔记/证据可**多归属**（M:N，同属多个容器）。
_Avoid_: 证据列表（实现层用语）、收藏夹（语义太弱，丢掉"主题"含义）

**笔记 / Note**:
用户对文献或综述的解读文字，单形态、纯文本（Markdown）。
【当前】只能在文献/综述里划词创建、必依附一个证据集，一个证据集只有一条。
【0.4 目标】一个证据集下可有多条；并探索**自由笔记**（不依附任何文献的凭空想法）。
_Avoid_: 假设 / hypothesis（已废弃形态，不再使用）、批注（窄化了"独立想法"的含义）

**证据 / Evidence（EvidenceRef）**:
指向某来源的引用锚点——文献段落、综述句子、或对话消息。是证据集里"被引用的材料"。
_Avoid_: 引用（与文献 citation 混淆）、引文

**证据粒度 / Evidence granularity**:
证据条目可在两种粒度上指向来源——**段落级**（划词选中的精确片段，引文即被划中的原文）与**对象级**（引用整篇论文/综述等来源对象，引文取其代表性文本：标题 / 摘要首段 / 章节名）。两者都必带一段 verbatim 引文（溯源的灵魂、去重身份），区别只在定位精度；详情页"补证据"产出对象级，精确段落仍由划词补。
_Avoid_: 把"对象级引用"理解成"无引文引用"——任何证据都带引文。

**补充证据 / Add Evidence**:
往一个已有证据集加入新证据的动作。
【当前】只能在 Agent 对话场景里选择已有证据集补充。
【0.4 目标】证据集详情页提供直接入口。

## Relationships

- 【当前】笔记 1:1 证据集；证据集 1:N 证据。
- 【0.4 目标】证据集 ⟷ 笔记、证据集 ⟷ 证据 均为 **M:N**（一成员可多归属）；证据集带标签与时间戳。
- 证据通过来源类型关联到 文献（Paper）/ 综述（Review）/ 对话（Conversation）。

## Flagged ambiguities

- **"证据集"的核心隐喻**：已裁决为"多归属研究主题容器（M:N）"（[ADR-007](../adr/ADR-007-evidence-set-topic-container.md)，0.4 P2 需求探索佐证）——证据集含 N 笔记 + N 证据，且一条笔记/证据可同属多个容器。
- **笔记能否游离**：已裁决**成立**——自由笔记是耐久一等公民（ADR-007 / 需求探索）；链接到证据为可选而非强制。
- **笔记 vs 证据关系**：并列（容器的 co-member，由引用/链接关联），非"笔记下挂证据"。
- **证据集 vs 文献库边界**：文献库是 Paper 的全集，证据集是用户主题性筛选+解读，二者不可混用。
- **"文献库"一词的二义**（0.5 grill 2026-06-02 钉死）：本仓 **文献库 = 个人文献库 / Library**——用户本地保存的 Paper 全集（设备级、`~/.asci/`，本条上一项即此义）。0.5 讨论中提到的 **"自建文献库"是另一个概念**——ASCI 服务端可能托管的**公共检索资产**，暂称 **文献语料 / Corpus**；且已裁决其形态为**相关性 / 策展层**（cache+index 开放数据 + AI 重排 + 学科种子集），**非**自托管原始语料。目前该服务端基础设施**不存在**（现架构纯本地优先，ADR-001；服务端仅认证+遥测，ADR-002）。二者存储位置/归属/是否已建均不同，不可混用。

# 研究空白（Research Gap · 0.4 新功能）

记录"在一组文献上找研究空白"领域的统一语言。**只新增「研究空白」一个术语**，其余全部锚定到已有术语（证据集 / 证据条目 / 笔记），不新造（术语极简原则）。0.4 做"所选的一组文献内"，0.5 扩到"领域级召回文献内"。

## Language

**研究空白 / Research Gap**:
在一组文献上，把每篇按可比属性排成一张**对照表**后——**没人填的属性组合（空格子）= 研究空白**，外加 AI 标出的结论冲突（打架）。**严格限定"在所选的这组文献内"**，不主张"全世界没人做过"。
_Avoid_: 假设 / hypothesis（「笔记」条目已废弃该词，不复用）；研究空白图谱 / 证据网格 / 圈定语料 / 拍板（均曾用、已废——分别回落为白话"对照表"、已有"证据集 / 证据条目"、白话"所选文献"、白话"用户判断"）。

## Relationships

- **输入 = 证据集（或选定的一组文献）**；产物（对照表 + 选中的研究空白）**沉淀回证据集**（成笔记/证据）。
- **对照表的每个格子 = 一条证据条目（EvidenceRef）**（带溯源锚点）——研究空白只是把已有的证据条目排成"文献 × 属性"的对照表，再看哪格是空的，**没有新原语**。
- 与【语义检索】互补：语义检索纵向"这一篇说了啥"，对照表横向"这 N 篇各取什么值"。

## Flagged ambiguities

- **"研究空白"的范围**：永远限定"在所选文献内"（0.4）或"在召回的领域文献内 + 显式披露召回边界"（0.5）——产品文案与 AI 输出**禁止**"全领域/全世界没人做过"措辞。
- **对照表的列**：AI 自动提议 + 用户增删改（非学科固定模板、非纯手建）。"对照表"是白话描述，不立为术语。
- **与"假设"废弃形态的关系**：本功能不复活「笔记」里已废弃的 hypothesis；产出的是可溯源的"空白/冲突"，不是 AI 生成的假设主张。

# Agent 编排（Orchestration）

记录"总控 Agent / 子 Agent 派发 / 多包协同"领域的统一语言。与"对话流"领域的【队友 Teammate】互为表里：编排是后台行为，队友是它在对话流里的呈现。

## Language

**总控 Agent / Supervisor**:
接收用户高层需求的主 Agent。先与用户**澄清需求**，再**自主编排**能力包的场景 Agent（队友）协同完成——派哪些包、什么顺序由 Supervisor 自主决定，**不由用户手动编排 workflow、也不是预定义流程**。
_Avoid_: 路由器（窄化为"选一个包"，丢掉"自主编排多包"）、workflow 引擎（ASCI 不用人定义的固定 workflow）

**需求澄清 / Clarification**:
Supervisor 在编排前与用户对齐意图的反问环节。是用户在"自主编排"前的主要控制点；澄清充分性直接决定编排质量。

**自主编排 / Autonomous Orchestration**:
Supervisor 基于澄清后的需求，动态决定调用哪些能力包队友、以何顺序协同。过程经对话流（执行步骤组 + 队友徽标）透明可见，用户审查最终产物。
_Avoid_: 工作流编排（workflow orchestration，暗示固定 / 人定义流程）

**包间协同契约 / Inter-Pack Contract**:
Supervisor 能自主编排多包的前提——每个能力包声明**能力描述**（供 Supervisor 判断何时派它）与**输入/输出**（供产物在队友间传递）。
_Avoid_: 与能力包四要素（场景 Agent/Skill/MCP/UI 框架）混为一谈——协同契约是四要素之外、面向 Supervisor 决策的声明。

## Relationships

- 用户高层需求 →【Supervisor 需求澄清】→【Supervisor 自主编排】→ 派多个【队友（能力包场景 Agent）】→ 过程经对话流透明 → 用户审最终产物。
- Supervisor 编排依赖【包间协同契约】；该契约是 0.2 预留的对象 JSON Schema / A2A 数据交换层的上层兑现。

## Flagged ambiguities

- **总控 Agent 的能力档位**：design-input（2 包时）设"单路由到一个包，多包协同推 V1"；0.4（4 包）升级为"Supervisor 自主编排多包协同"。这是对 design-input §五"首发 2 包不相互调用"的反转，需 ADR。
- **用户控制点**：用户在"需求澄清"控制，澄清后放手给 Supervisor（不强制节点审查）；过程透明但默认不阻塞。中途可否喊停/纠偏 = 待定的安全阀。

# 文献检索数据服务（Literature Relevance Service，0.5 方向 · 未实现）

> ✅ **方向已裁决**（2026-06-02，经 grill + 2 轮 deep-research 佐证）：0.5 取「**部分自建分层**」——自建 OpenAlex 元数据索引 + 可合法再分发的预处理全文，按需现抓守许可红线，最大投入在 agentic 检索/重排软件层（跑 BYOK）。完整架构/许可/成本/反转见 [ADR-013](../adr/ADR-013-literature-relevance-service.md) + [0.5 north-star](../milestones/0.5/north-star.md)。**尚未实现**；本节仅记录领域术语。与上文「个人文献库」严格区分。

## Language

**文献语料 / Corpus**:
ASCI **服务端**托管的公共论文检索资产，取「部分自建分层」：**自建**=OpenAlex 全量元数据索引 + 可合法再分发的预处理全文（peS2o/S2ORC 的 ODC-By、PMC oa_comm 的 CC0/CC-BY，XML/纯文本）；**按需现抓+外链不落库**=arXiv、非 OA、CC-NC/ND 论文（守许可红线）；**不做**全量语义向量 embedding。
全文/解析的入库有两条管道：**批量摄取**（ADR-013 P1，eager）+ **需求驱动懒填**（ADR-014，按用户精读需求补 OA，见下「需求驱动语料填充」）。
_Avoid_: 文献库（用户本地的【个人文献库 / Library】，不可混用）、自建论文库（暗示囤全量原始全文——只自建可合法再分发的 OA 子集）

**智能检索 / Smart Search**:
跑在 Corpus 之上的相关性能力——agentic 迭代检索 + 混合(BM25⊕dense)召回 + LLM 重排 + 全文 RAG 精读，把 canonical 顶上来、紧扣专业。是 0.5 的**差异化软件层**；**重排/检索智能默认跑用户 BYOK key**（ASCI 零每查询推理成本），服务端只托管索引/语料。
_Avoid_: 检索（裸 BM25 / fan-out 也叫检索，需限定"智能"以区分）

**相关性 / 策展（Relevance / Curation）**:
"做别人做不到的点"所在——**不靠囤论文，靠 AI 把对的论文排到前面 + 把全文预处理好让精读秒开**。可防御资产 = 相关性/精读软件质量 +（0.6 起）查询飞轮，而非原始语料本身（印证 0.2 moat-analysis：护城河在软件+飞轮）。

**无 API 源接入 / Non-API Source Access（0.5+ 方向 · 见 [ADR-014](../adr/ADR-014-non-api-sources-and-demand-driven-fill.md)）**:
对**不提供 API 的平台**（Google Scholar 为标杆，未来 ResearchGate / CNKI / 万方 / 出版商页）的检索接入。数据 ToS 禁抓 + 不可缓存再分发 → **实时现抓 + 外链、永不落 Corpus**；抓取**默认跑用户本地**（用户 IP/会话），用户可自配**第三方 SERP API key（BYOK）兑底**，**ASCI 服务端永不自抓**（守本地优先 + BYOK 零成本零法律风险）。
_Avoid_: 爬虫/抓取（裸词不带"无 API 源"语义，且易被读成 ASCI 服务端自抓——已明确排除）。

**需求驱动语料填充 / Demand-driven Corpus Fill（0.5+ 方向 · 见 [ADR-014](../adr/ADR-014-non-api-sources-and-demand-driven-fill.md)）**:
给 Corpus 的批量摄取（ADR-013 P1）**叠加的一条按需懒填管道**：用户对某 OA 论文发起精读时，客户端发**去关联的"需 DOI Y"信号**，**ASCI 服务端自取该 OA + 自解析**入共享缓存供所有人二次调用。**贡献模型 = 信号驱动 + 服务端自取自解析**（非"用户上传自己的解析副本"）——由此规避投毒（ASCI 控解析质量）、版权转分发（ASCI 直取 OA，不转用户副本）、重隐私（收敛为纯需求信号）。**仅可再分发 OA 入共享**；非 OA / arXiv / NC-ND 服务端取不到 → 永不进共享，至多设备本地缓存（ADR-013 R3）。默认关、opt-in + 去关联。
_Avoid_: 用户贡献文献库 / 上传解析（暗示用户上传副本——已否；是服务端自取自解析）、查询飞轮（那是 0.6 的相关性信号飞轮，与本条正交，见 Flagged ambiguities）。

## Relationships

- 用户查询 →【智能检索】在【文献语料】上 agentic 召回+重排 → 秒回紧扣专业的结果；命中可合法缓存语料则精读秒开，否则按需现抓+外链。
- 与现有【个人文献库】正交：Corpus 是公共资产（服务端），个人文献库是用户保存的子集（本地）。

## Flagged ambiguities

- **"不自建文献元数据库" vs ADR-013"自建 OpenAlex 元数据 index"**（0.5+ grill 2026-06-03 钉死）：不冲突。**镜像 OpenAlex 开放数据 = 复用，不算"自建元数据库"**——「不自建元数据库」指不造自有专有目录、不做元数据权威方（"不囤论文，囤相关性"）；OpenAlex 全量 index 仍**自托管**（ADR-013 P1 不变）。用户驱动回流的是**解析后全文/精读数据**，属另一层（见下「需求驱动语料填充」），不是元数据。
- **Corpus vs 个人文献库**：同名"库"不同物，不可混用（见「证据集与笔记」§Flagged ambiguities 同名条）。
- **需求驱动语料填充（内容飞轮）vs 查询飞轮（信号飞轮）**（0.5+ grill 2026-06-03）：两个不同飞轮，正交、勿混。**需求驱动语料填充**回流**公共 OA 论文内容**（DOI-keyed、去关联），目的填全文缓存；隐私面轻（纯需求信号），**0.5 opt-in 即做**。**查询飞轮**回流**查询/点击/采纳信号**，驱动相关性复利；含 per-user 研究行为，撞 0.3 红线更重，**0.6 才碰**。
- **无 API 源接入 vs OpenAlex 覆盖**（0.5+ grill 2026-06-03）：互补非替代。OpenAlex（自托管 index）覆盖开放世界元数据长尾；无 API 源（GS 类）补 OpenAlex 缺的（灰文献、引文发现、非英文、学位论文、部分非 OA）。GS 在扩源 spec §4.2 曾因"抓取脆/封 IP"列黑名单死源——ADR-014 以 **user-local 抓取 + spike 量化可用率 + 观察档**重评，**非**复活服务端 fan-out。
- **变现 / 0.6 查询飞轮 / 隐私红线** = 产品决策，归 ADR-013 + 0.5 north-star。freemium 为**可选**（非成本逼出，但信誉修复须在免费层）；0.6 查询飞轮与 0.3"行为遥测绝不含研究内容"红线相撞（查询词=潜在研究内容），0.5 不碰。

# 文献语料与检索（Literature Corpus & Retrieval）

记录"文献全文 / LLMWiki / 语义检索"领域的统一语言，供产品与工程在讨论文献问答、综述加速、证据组装时对齐。

## Language

**LLMWiki / 文献增强阅读**:
对已解析文献逐段生成摘要与关键术语标注的 LLM 增强产物（每篇文献一份，与原文段落一一对应）。
既服务人的增强阅读，也作为**语义检索**的高信号语料层。
_Avoid_: article 生成（实现层用语）、wiki（裸用易与"wiki 语料目录"混淆）

**向量索引 / Vector Index**:
文献语料的**可重建派生缓存**：把语料切块嵌入后支持按语义相似度召回。
全局一份、跟随文献库（不按工作区分裂）；可随时删除重建，不属于用户数据。
_Avoid_: 向量库/知识库（暗示一等数据资产——它只是缓存）、RAG（一揽子词，掩盖"检索"与"生成"的边界）

**语义检索 / Semantic Search**:
用自然语言查询在全库文献中召回相关**段落**（带回原文锚点）的能力。
由 Agent 在问答/综述时自主调用；与逐篇精读互补——先召回再决定深读哪里。
_Avoid_: 模糊搜索（语义≠模糊）、全文搜索（那是关键词路）

**混合检索 / Hybrid Retrieval**:
语义（向量）与关键词（精确术语）两路召回的融合。科研查询常含精确术语
（基因名/方法缩写/作者名），单靠语义会漏，单靠关键词不泛化。

**评估开关 / Evaluation Toggle**:
门控"语义检索是否参与 Agent 工作流"的总开关：关闭后 Agent 回到逐篇阅读基线，
用于 A/B 对比语义检索的实际价值。

## Relationships

- 文献解析产出 raw 全文 → 可选生成【LLMWiki】→ 两者 + 篇章摘要共同构成【向量索引】的三层语料。
- 【语义检索】命中的段落锚点 + 原文片段可直接转化为【证据 / EvidenceRef】——这是"检索提升证据组装质量"的闭环。
- 【向量索引】作用域跟语料（文献库，全局）；【证据集】作用域跟用户（工作区）——二者作用域不同，查询期过滤衔接。

## Flagged ambiguities

- **"检索证据集本身"**：当前不做（等 ADR-007 M:N 容器落地、证据集规模变大后再议）；现阶段"语义检索"只检索文献语料。
- **嵌入来源**：已裁决本地模型优先（[ADR-012](../adr/ADR-012-local-embedding-vector-index.md)）；远程 embeddings API 是未来扩展而非首期路径。

# 遥测埋点（Telemetry）

记录"崩溃上报 / 行为埋点 / 自进化信号"领域的统一语言。架构决策见 [ADR-011](../adr/ADR-011-telemetry-architecture.md)，实现地图见 [telemetry-spec](../specs/telemetry-spec.md)。

## Language

**埋点三层 / Three Telemetry Layers**:
Sentry 崩溃上报（恒开、脱敏）、PostHog 行为埋点（toggle ①）、自进化信号（toggle ②，独立通道）。三层互不依赖，前两层是 0.3 发布运维底线。
_Avoid_: 把三层笼统称"埋点开关"——Sentry 无开关，两 toggle 各管一层且解耦。

**deviceId（匿名设备标识）**:
本地生成的 UUID，行为事件与信号的归属键。#420 登录落地前的唯一身份；落地后经 identify/alias 合并到账户，本身不变。
_Avoid_: 用户 ID（它不含也不可逆推任何用户信息）。

**consent 模式 / opt-in vs opt-out**:
GDPR 区（含 EEA/UK，时区启发式判定，无法判定按 GDPR 区）默认关、需显式开启 = opt-in；其余默认开、可随时关闭 = opt-out。用户显式选择持久化后优先于地域默认。
_Avoid_: "欧盟 IP 判定"（实现为本地时区启发式，不查 IP——见 ADR-011 §2）。

**采集入口全停 / Full-Stop Gate**:
consent 关闭的语义：不写本地缓冲也不上报，而非"本地照写、只闸上报"。
_Avoid_: 上报开关（窄化，会暗示本地仍在记录）。

**自进化信号 / Self-Evolution Signal**:
5 类结构化信号（任务结构、工具使用、模型选型、错误异常、工作区结构）+ 隐式反馈。字段范围以 `schema/telemetry/*.schema.json`（Zod 生成，tracked）为审计事实源；出口前 Zod strip = 白名单。
_Avoid_: 6 类（Proposal 决策信号已随 Proposal 移出 0.3）。

**隐式反馈 / Implicit Feedback**:
用户对 Agent 产出的非显式质量信号：copy / save / cite / discard / retry（thumbs_up/down 为枚举占位，0.3 无 UI）。只采动作与对象类型，不采内容。

**脱敏红线 / Redaction Red Line**:
任何出口绝不含：文献全文、PDF、笔记原文、对话原文、检索词、凭据、邮箱、IP、用户名及含用户名路径（路径用户名段 → `<USER>` 占位符）。

## Relationships

- renderer 显式埋点 → IPC → 主进程 telemetry-service（唯一闸口：consent → 白名单 → 脱敏 → deviceId 注入）→ SaaS / 本地 JSONL。
- 事件名 + 属性白名单的事实源 = `packages/shared/src/telemetry/event-registry.ts`（调用点禁裸字符串）。
- 自进化 sender 可插拔：后端（ADR-002）就绪前仅本地 `signals.jsonl` 缓冲。

## Flagged ambiguities

- **T-6（自进化端点落库）**：等 ADR-002 后端拍板，本期以本地 JSONL 代偿。
- **赞踩 UI**：schema 已留枚举位，UI 另开 issue。
- **native minidump 脱敏**：Crashpad 二进制转储无法客户端脱敏（不含 ASCI 注入的用户字段），为 Sentry 已知边界。

# 数据所有权（Data Ownership）

记录"数据导出 / 对象标准"领域的统一语言，供产品与工程在讨论 GDPR 可携带权（Art.20）、
开放标准生态位时对齐术语。（grill 会话 2026-06-02，issue #419 / PRD 0.3.0 Epic 4）

## Language

**导出包 / Export Bundle**:
用户从 Settings 账户 tab 一键导出的 zip 文件，包含全部本地研究对象（6 类持久对象）、
清单（manifest）、对象标准 schema 副本与综述正文。是 GDPR Art.20 可携带权的落地形态。
_Avoid_: 备份 / backup（暗示可恢复回 ASCI，0.3 不承诺导入）、dump（私有格式含义，违背开放标准定位）

**对象标准 / Object Standard（O1 Schema）**:
核心对象的开放 JSON Schema，从 TS 类型这一**唯一真相源**生成，落仓库 `schema/objects/`。
目标是外部工具无需读 ASCI 源码即可解析导出包（BibTeX / Zotero CSL 生态位）。
_Avoid_: 内部 schema（它是对外契约，不是内部约束）

**清单 / Manifest**:
导出包内的自描述文件，记录导出时间、应用版本、对象计数与"数据文件 ↔ schema"对应关系。
导入方应先读清单再解析数据。

## Relationships

- 一个 **导出包** 内每类对象一个 JSON 数组文件，逐条符合 **对象标准**；**清单** 描述全包。
- 软删（visibility='deleted'）对象**在导出包内**——导出是完整携出而非视图；导入方按 visibility 自行过滤。
- 综述（Review）元数据在 JSON 内、正文是包内独立文件，元数据以包内相对路径指向正文。

## Flagged ambiguities

- "6 个核心对象"有两套口径：导出覆盖 6 类**持久**对象（含 Review、无 Proposal——Proposal 无持久化表）；
  对象标准 schema 生成覆盖全部 7 个 TS 对象（含 Proposal，供 #243 文档化）。
- 导出 ≠ 备份：0.3 只承诺"带走"（可被第三方解析），不承诺"导回"（导入功能不在范围）。
